# TRACE-RPG Experimental Game Studio — repository operating rules

This is the single canonical contract for game-studio work in this project. Apply it together with
the root `../AGENTS.md`, code, tests, and live artifacts under `_workspace/current/`. The root
contract owns research evidence; this file owns production lanes and engine execution.

Generated by `game-studio-harness` and refreshed for run
`20260813-sealed-lighthouse-cycle-3`.

## 1. Workspace: one live folder, one archive

`_workspace/current/` is the only live studio folder. Do not create dated siblings. A new cycle
updates `current/` in place and records the transition in
`_workspace/current/production/task-manifest.md`.

```text
_workspace/
  current/
    intake/ design/ pm/ engineering/ qa/ ops/ ui/ production/
    messages/ retrospectives/
  archive/<run-id>/
```

- Write live studio artifacts only under `_workspace/current/`. Engine source, schemas, fixtures,
  paper sources, and durable public documentation remain in their owning repository paths.
- Treat `_workspace/archive/**` as immutable. At cycle close use `git mv`, never deletion, and add
  `current/retrospectives/cycle-<n>-retrospective.md`.
- Treat promoted engine evidence as immutable. `scripts/capture_godot_evidence.py` requires a new
  `--evidence-set-id`, captures under non-authoritative staging, and fails rather than overwriting an
  existing evidence set.
- Treat render captures as a separately identified, non-headless presentation pass over the
  already-authored canonical fixture. Each promoted PNG must be bound to its source run/event or
  state beat, exact source hashes, dimensions, byte count, SHA-256, display/render metadata, and
  capture method before it can be cited.
- Treat Cycle 3 `--shot` PNGs and `--evaluate` JSON as working engineering artifacts. They are not
  immutable evidence unless a new unique evidence set is promoted under the existing capture
  contract; they never establish G4, G6, usability, immersion, affect, or efficacy by themselves.
- Treat `research/academic-pipeline/rq2-live-pilot/` as a separate `screening-pilot-only` lane
  (D-049). Its 14-file promotion manifest may support only `C-PILOT-007/008`; it must not alter the
  frozen offline denominators or promote any `C-RESULT-*` claim from `TODO-RESULT`.
- Treat `research/simulation/kg-ontology/` as a separate `simulation-only` methods-graph lane
  (D-051). `SL-KG-ONTOLOGY-SIM-001` may measure only authored closed-world typed-link recovery.
  The generated SQLite mirror is ignored and non-authoritative; it must not replace Graphify,
  `WorldState`, the validator, or support any `C-RESULT-*` claim. Run its `--check` gate after any
  OKF atom, ontology, curated relation, metric formula, claim boundary, or generator change.
- Label potentially ambiguous statements `[OBSERVED]`, `[INFERENCE]`, or `[TARGET]`. A design target
  is not a measured game result.
- Every gate claim cites the measurement, method/command, timestamp, and repository-relative
  evidence path. Missing evidence is `FIX`, never PASS.
- Treat the Stage-5 citation entry list as the source of truth for its redundant totals; the
  crosswalk validator must re-derive and reject stale summaries. The fixed 58/48/10/22 release
  baseline changes only with an intentional bibliography revision. When official records disagree,
  preserve the conflict and follow the paper-owned record for citation order (D-069).
- `production/decision-log.md` is append-only. Reread its tail, verify the next ID is unique across
  `_workspace/`, and abort on collision.
- Re-derive this file whenever a lane, generator, engine entry point, authority boundary, gate,
  regression command, evidence promotion boundary, or hard-won invariant changes. Record the refresh in both
  `production/task-manifest.md` and `production/decision-log.md`.
- Current generated concept outputs are `game-track/assets/concepts/*.png`. They are not a source
  of empirical truth and cannot be promoted without adjacent provenance, rights review, hashes,
  and a curation decision.
- Public Web and `--public-safe` runs must not load generated candidate images from
  `game-track/assets/concepts/` or `game-track/assets/concepts/pack-3d/`. These candidates remain
  `runtime_eligible: false` until human rights/style review and explicit curation. The only
  generated assets allowed in public builds are the curated, provenance-bound PNGs under
  `game-track/godot/assets/ui/` (D-034/D-035; case-file board, evidence-card icons, compass, and
  investigate vignette added by D-073), the validated tracked Higgsfield player GLB under
  `game-track/godot/assets/player/` (D-050), and the Higgsfield evidence-desk prop
  `game-track/godot/assets/models/evidence_desk.glb` recorded in `models-manifest.json`'s
  `ai_generated_assets` block with adjacent provenance (D-073). The world must still build and pass
  the smoke when any of them is absent.
- Never commit `.env`, access tokens, `~/.codex/auth.json`, Godot editor caches under `.godot/`, or
  raw participant/personal telemetry.

## 2. Engine perspective: headless evidence plus separate playable, capture, and Web passes

This is a Godot 4.x headless-first, turn-based narrative investigation micro-RPG with a separate
playable 3D presentation. Engine entry points are the canonical `game-track/godot/project.godot`
defaulting to `res://scenes/headless.tscn`, the explicit playable
`game-track/godot/scenes/main_3d.tscn`, the deterministic archetype balance probe
`game-track/godot/scenes/balance_probe.tscn` (D-038), the retained non-headless capture runner,
and versioned contracts under `game-track/schemas/`. The public Web builder is
`scripts/build_godot_web.sh`. Interactable layout and the refusal next-affordance mapping have a
single owner, `scripts/game3d/golden_path_layout.gd`, shared by the playable slice and the probe.

- Lifecycle order is prototype → systems → content → assets → feel → performance → QA → release.
- Godot owns observation rendering, player input, local save/load, and engine telemetry. Legacy
  ENG1 mirrors authored hard policy for engine-local conformance; it does not execute the core
  E1/E2 Python hard-policy authorization round trip, which remains unimplemented in the game.
- The additive NPC v1.1.0 path is separate: Codex proposes untrusted typed intent in P; Python
  validates schema/public claims and computes public-projection plans; Godot alone authorizes and
  commits canonical change. Native012 proves one source-bound Godot–HTTP–Codex engineering
  demonstration, not integration of the core Python hard-policy authority or efficacy.
- The non-headless capture runner may render only frozen, deterministic beats derived from the
  authored fixture/run packet. It does not authorize actions, revise canonical state, call a model,
  or replace the headless conformance run.
- The playable 3D pass may add movement, player mesh/animation, focus, English UI, VFX, local audio,
  and working screenshots, but these systems may only read committed snapshots or emit proposal
  intent. Only the hard writer may mutate canonical state. Never add rig identity, transforms, or
  clip state to saves, schemas, or `canonical_state.gd`.
- Web export must copy the Godot project to a disposable directory, select `main_3d.tscn` only in
  that copy, subtract only the exact audited sandboxed macOS font/certificate diagnostics, and fail
  on every remaining import/script error. Never run Godot editor/import, smoke, evaluation, Web
  export, or screenshot capture against the real `game-track/godot` project; use a disposable
  staged copy and verify the canonical `project.godot` SHA-256 remains
  `2e7966bf2ac6b54bfaf2db84b3f446686436bd3a1f8efea592ffa82e91249edd`.
- Browser pointer capture and audio resume must begin from an explicit user gesture. Provide a
  visible start gate, cursor-release/recovery state, audio mute, and reduced-motion control.
- The canonical episode payoff is restoration of the harbor-side signal and acquisition of the
  tide route while the offshore lighthouse remains dark and sealed. Runtime copy or assets must
  not imply lighthouse entry, reopening, or lighting in this slice.
- Render-capture PNGs establish only authored engine-render/state correspondence. They are not
  evidence of usability, immersion, input latency, frame performance, player benefit, model
  efficacy, semantic-oracle completeness, G4, G6, or a live Python transport.
- The primary capture surface is structured state/text with programmatic engine graphics. Generated
  concept images remain excluded; if later shown, they must use the separately labelled
  `secondary-vlm-ui` track with their own provenance and analysis.
- The public-safe playable surface uses a procedural world/VFX/audio base, the curated UI art lane
  `game-track/godot/assets/ui/` (D-035), and the curated tracked Higgsfield player
  `game-track/godot/assets/player/higgsfield-player.glb` (D-050). UI PNGs degrade to the
  programmatic fallback when absent; the player GLB must pass `scripts/validate_player_asset.py`
  with `Idle` and `Casual_Walk`. This is a release/presentation lane, not a third research authority
  or confirmatory visual arm.
- Player-visible runtime UI is English-only and ASCII-safe under the bundled font. Preserve the
  existing text+icon redundancy with bracket markers; decorative glyphs such as `◂ ▸ ✔ ✖ ☀ ◈ ● ○
  ┄ ─ ┤` must not re-enter runtime strings.
- Presentation may read a committed snapshot but never mutate canonical state directly.
- Below-world recovery is physical presentation recovery only: when `y < -3.0`, return to
  `(0.0, 0.2, 2.0)`, clear velocity, and leave the complete symbolic state hash unchanged (D-048).
- Timeout, invalid proposal, controller failure, exhausted repair, or physical fall recovery must
  leave the complete prior canonical state unchanged.

## 4. Role and review separation

- Director: scope, gate verdicts, arbitration, and cycle closure.
- Designer: concept, worldview, core loop, balance targets, novelty, and presentation.
- PM: zero-economy policy, schedule, reward pacing, and experiment resource forecast.
- Programmer: Godot build, bridge, deterministic replay, telemetry, and rollback.
- QA: independent measurements, defects, exploit checks, and regression evidence.
- Game integrator independently reviews engine/research hash equality.
- Logic auditor independently reviews policy/oracle separation and semantic counterexamples.
- No artifact author approves their own high-risk gate.

Production lore QA and the hidden research oracle are separate artifacts with separate owners. A
zero-economy research override replaces the harness's monetization assumptions; do not fabricate a
paid/free result.

## 5. Concurrent-session Git safety

- Assume concurrent edits. Before staging, acquire `.git/game-studio.lock` atomically with `mkdir`,
  record the session owner, and stop if it already exists. Remove it only after commit/push or an
  explicitly recorded abort. A lock whose owner session no longer exists (`aside session list`,
  process table) and whose patch has sat unstaged across a later release pass may be taken over
  only after recording the takeover, the consumed decision IDs, and every other live session's
  footprint in `_workspace/current/conflicts.md`; rename the stale lock, never delete it silently.
- Run `git status --short` before edits and immediately before committing.
- Stage explicit pathspecs only. Never use `git add -A`, `git add .`, destructive cleanup, reset,
  or force-push.
- Fetch the explicit upstream and inspect `@{upstream}..HEAD` before pushing. Unknown commits block
  the push until inspected.
- Do not restore or overwrite another session's changes. Record collisions in
  `_workspace/current/conflicts.md`.
