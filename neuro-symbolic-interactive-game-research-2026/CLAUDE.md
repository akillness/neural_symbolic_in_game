# TRACE-RPG Experimental Game Studio — repository operating rules

This is the single canonical contract for game-studio work in this project. Apply it together with
the root `../AGENTS.md`, code, tests, and live artifacts under `_workspace/current/`. The root
contract owns research evidence; this file owns production lanes and engine execution.

Generated by `game-studio-harness` and refreshed for run
`20260813-sealed-lighthouse-cycle-2`.

## 1. Workspace: one live folder, one archive

`_workspace/current/` is the only live studio folder. Do not create dated siblings. A new cycle
updates `current/` in place and records the transition in
`_workspace/current/production/task-manifest.md`.

```text
_workspace/
  current/
    intake/ design/ pm/ engineering/ qa/ ops/ ui/ production/
    messages/ retrospectives/
  archive/<run-id>/
```

- Write live studio artifacts only under `_workspace/current/`. Engine source, schemas, fixtures,
  paper sources, and durable public documentation remain in their owning repository paths.
- Treat `_workspace/archive/**` as immutable. At cycle close use `git mv`, never deletion, and add
  `current/retrospectives/cycle-<n>-retrospective.md`.
- Treat promoted engine evidence as immutable. `scripts/capture_godot_evidence.py` requires a new
  `--evidence-set-id`, captures under non-authoritative staging, and fails rather than overwriting an
  existing evidence set.
- Treat render captures as a separately identified, non-headless presentation pass over the
  already-authored canonical fixture. Each promoted PNG must be bound to its source run/event or
  state beat, exact source hashes, dimensions, byte count, SHA-256, display/render metadata, and
  capture method before it can be cited.
- Label potentially ambiguous statements `[OBSERVED]`, `[INFERENCE]`, or `[TARGET]`. A design target
  is not a measured game result.
- Every gate claim cites the measurement, method/command, timestamp, and repository-relative
  evidence path. Missing evidence is `FIX`, never PASS.
- `production/decision-log.md` is append-only. Reread its tail, verify the next ID is unique across
  `_workspace/`, and abort on collision.
- Re-derive this file whenever a lane, generator, engine entry point, authority boundary, gate,
  regression command, evidence promotion boundary, or hard-won invariant changes. Record the refresh in both
  `production/task-manifest.md` and `production/decision-log.md`.
- Current generated concept outputs are `game-track/assets/concepts/*.png`. They are not a source
  of empirical truth and cannot be promoted without adjacent provenance, rights review, hashes,
  and a curation decision.
- Never commit `.env`, access tokens, `~/.codex/auth.json`, Godot editor caches under `.godot/`, or
  raw participant/personal telemetry.

## 2. Engine perspective: Godot 4.x headless-first with a separate render-capture pass

This is a Godot 4.x headless-first, turn-based narrative investigation micro-RPG. Engine entry
points are `game-track/godot/project.godot`, the headless scenario runner and separate non-headless
capture runner under `game-track/godot/scripts/`, and versioned contracts under
`game-track/schemas/`.

- Lifecycle order is prototype → systems → content → assets → feel → performance → QA → release.
- Godot owns observation rendering, player input, local save/load, and engine telemetry. In the
  current headless fixture it also mirrors an authored hard policy solely for engine-local
  conformance; this mirror is not the target authority boundary.
- The Python research runtime is the target hard-policy authority. A live authorization round-trip
  has not executed. Until it does, only supported Godot events are projected into the stable bridge
  envelope and schema-tested; no cross-runtime integration claim is permitted.
- The non-headless capture runner may render only frozen, deterministic beats derived from the
  authored fixture/run packet. It does not authorize actions, revise canonical state, call a model,
  or replace the headless conformance run.
- Render-capture PNGs establish only authored engine-render/state correspondence. They are not
  evidence of usability, immersion, input latency, frame performance, player benefit, model
  efficacy, semantic-oracle completeness, G4, G6, or a live Python transport.
- The primary capture surface is structured state/text with programmatic engine graphics. Generated
  concept images remain excluded; if later shown, they must use the separately labelled
  `secondary-vlm-ui` track with their own provenance and analysis.
- Presentation may read a committed snapshot but never mutate canonical state directly.
- Timeout, invalid proposal, controller failure, or exhausted repair must leave the complete prior
  canonical state unchanged.
- Use Godot/GDScript guidance only. Unity editor, prefab, package, or C# assumptions do not apply.

## 3. Asset generation: one owner per class

| Asset class | Tool | Invocation |
|---|---|---|
| Environment key art | `god-tibo-imagen` | `gti --prompt <frozen-prompt> --size 1536x1024 --output <asset.png>` |
| Character exploration sheet | `god-tibo-imagen` | `gti --prompt <frozen-prompt> --size 1536x1024 --output <asset.png>` |
| UI concept | `god-tibo-imagen` | `gti --prompt <frozen-prompt> --size 1536x1024 --output <asset.png>` |
| Evidence/item icon sheet | `god-tibo-imagen` | `gti --prompt <frozen-prompt> --size 1536x1024 --output <asset.png>` |
| Paper diagrams and measured plots | repository SVG/Python generators | `uv run python scripts/generate_paper_figures.py` |

- Validate every image prompt with `gti --dry-run` before spending quota.
- Generate one style anchor before the full set.
- Every PNG has adjacent provenance recording exact prompt, reference inputs (including an empty
  list), tool/package, provider/model, UTC time, dimensions, bytes, SHA-256, curation state,
  intended track, and `runtime_eligible: false`.
- `god-tibo-imagen` uses an unsupported private backend. It is an offline authoring tool only and
  must never become a game or experiment runtime dependency.
- The primary confirmatory track uses structured text/state. Frozen images may enter only the
  separately labelled secondary VLM/UI track.
- Generated images require AI-use disclosure and human rights/style review before publication or
  playable-build promotion.

## 4. Role and review separation

- Director: scope, gate verdicts, arbitration, and cycle closure.
- Designer: concept, worldview, core loop, balance targets, novelty, and presentation.
- PM: zero-economy policy, schedule, reward pacing, and experiment resource forecast.
- Programmer: Godot build, bridge, deterministic replay, telemetry, and rollback.
- QA: independent measurements, defects, exploit checks, and regression evidence.
- Game integrator independently reviews engine/research hash equality.
- Logic auditor independently reviews policy/oracle separation and semantic counterexamples.
- No artifact author approves their own high-risk gate.

Production lore QA and the hidden research oracle are separate artifacts with separate owners. A
zero-economy research override replaces the harness's monetization assumptions; do not fabricate a
paid/free result.

## 5. Concurrent-session Git safety

- Assume concurrent edits. Before staging, acquire `.git/game-studio.lock` atomically with `mkdir`,
  record the session owner, and stop if it already exists. Remove it only after commit/push or an
  explicitly recorded abort.
- Run `git status --short` before edits and immediately before committing.
- Stage explicit pathspecs only. Never use `git add -A`, `git add .`, destructive cleanup, reset,
  or force-push.
- Fetch the explicit upstream and inspect `@{upstream}..HEAD` before pushing. Unknown commits block
  the push until inspected.
- Do not restore or overwrite another session's changes. Record collisions in
  `_workspace/current/conflicts.md`.

## 6. Verification and reporting

- Full game-track regression command: `./scripts/validate_game_track.sh`.
- A render capture is valid only when the run used a non-headless display driver, awaited a rendered
  frame, produced the registered dimensions, passed non-blank/opacity checks, and was promoted with
  the source-run and file-digest metadata. A headless PNG substitute is invalid evidence.
- `experimental-game-event.schema.json` uses logical `sequence` plus unique contiguous
  `delivery_index`; duplicate deliveries reuse the logical event ID/sequence.
- Report exact commands and observed outputs. Separate carried evidence, new evidence, blockers,
  targets, and human-only judgments.
- G1--G8 use `_workspace/current/qa/gate-measurements.md` as the numeric source and
  `_workspace/current/production/gate-reviews/` for director verdicts.
- The current cycle may only pass a draft gate with direct evidence. G2--G5 and final G6--G8 remain
  `FIX` until their required simulations, archetypes, participants, or performance runs exist.
- Leave the workspace pick-up-ready: task status, latest verified command, owner, blocker, and next
  beat must be readable without chat history.
