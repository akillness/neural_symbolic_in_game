\section{타당성 위협, 한계 및 결론}\label{sec:conclusion}
\textbf{한계와 타당성 위협.} 핵심 패키지 \texttt{nesy\_game.multihop} 통합, 3단계 교란이 모두 제거된 \textbf{P11}--\textbf{P14} 라이브 평가(5개 월드 + 제품 \texttt{SealedLighthouseMachine} Godot~4.7.1, 480건 Datalog, 720회 우회) 후에도 네 가지 경계가 유지된다. 첫째, 라이브 CLI 실험(\texttt{agy} \texttt{cli\_version~1.5.12} 및 \texttt{claude-code-cli} \texttt{sonnet} medium)은 미인증 제공자 리비전·비시드 디코딩과 모든 파싱 실패(\textbf{P11} GPT-OSS 11/30턴, \textbf{P12} 6/30건, \textbf{P13A} 16/55턴, \textbf{P13B} 2/21턴, \textbf{P14} 2/144건)를 전체 분모에 보존한다(과거 3단계 교란은 \textbf{P11}--\textbf{P14}로 대체됨). 둘째, 사전 등록 180단위 인증 API 프로토콜은 \texttt{0/180} (\texttt{NOT\_RUN/BLOCKED}) 상태다. 셋째, 5개 월드(최대 8방·3역할)와 $R{\le}64, d{\le}5$ 그래프는 구조화된 상태 기계이지 자유 3D 오픈월드 플레이가 아니다. 넷째, 인간 평가($N{=}0$)는 미실행이므로 블라인드 36문항 \texttt{TR01--TR06} 패킷(\texttt{AWAITING\_}\allowbreak\texttt{HUMAN\_}\allowbreak\texttt{RATERS})에는 합성 라벨이 없으며 사용성·몰입감·인간 Krippendorff~$\alpha$ 주장은 배제한다.

\textbf{결론.} \system{}는 \texttt{nesy\_game.multihop}의 다중 홉 Datalog 폐쇄·7술어 검증기·상태 비참조 수리 $\rho(a,E)$·해시 연결 리플레이로 제안과 커밋 권한을 엄격히 분리한다(정리 1--4, \textbf{I1--I4}). Claude~Sonnet~5.5, GPT-OSS~120B, Gemini~4~Hydrogen·3.8~Flash 전반의 교란 제거 4단계 검증은 비유도 협상(\textbf{P11}: 30/30 무누출·0/79 위험 대 Safe-RL 37/79·NeMo 43/79), 5월드 실딩(\textbf{P12}: 0/84 대 54/84·55/84), 42회 비유도 Godot~4.7.1 실행(\textbf{P13}: 42/42 0-LLM 재실행 일치, Claude·Hydrogen 14/14 목표, 유출 0/42)을 입증하였다. 또한 $(a,E)$ 동등 조건 수리 비교는 $\rho_{K=2}$(27/27, 0토큰)가 매칭 LLM 수리(26/27, 530k--542k토큰, $p{=}1.0$)와 정확도 동등성을 유지하면서 토큰·지연을 제거하고 정리~2 거부 시 LLM 재선정(52/55)과 상보적임을 보였으며, 720회 3계열 우회 합의(Fleiss $\kappa{=}0.9367$), \texttt{DATASHEET\_v4.md}, Croissant~1.0 v4(22/22 SHA-256)를 제공한다.
