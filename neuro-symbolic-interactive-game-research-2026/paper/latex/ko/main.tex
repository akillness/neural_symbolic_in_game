\begin{abstract}
\system{}은 외부 결정론적 권한 검사, typed-error 수리($\rho$), 불변 fallback, 커밋 전 재검증, 의미적 replay, 배정 완결 계수를 결합하며, 읽기 전용 한·영 ontology view는 출처 선언을 공개 관측에 결속한다.

본 논문은 세 활성 관측 레인을 보고한다: (1) \texttt{gpt-6.1-sol} 기반 단일 Codex dashboard 사례($n{=}1$, 독립 반복 $0$)에서 모바일 geometry 수리, 62/62 검사 통과, Godot Web build, 실제 입력 거절·공개·재표시 달성; (2) 단일 authored quest 고정 게임 native pilot(seed 20261024; 8 assigned, 7 observed)에서 5건의 시스템 목표 달성, 1건의 응답 전 직렬화 기술 실패(미재실행), 2건의 \texttt{gpt-6.1-sol} ontology timeout과 함께 host 호출 23회, repair 0회, unsafe 전이 0/16, 유효 semantic replay 7건, 유효 fresh-engine 재실행 6건(1 \texttt{NOT\_RUN}, 1 미관측); (3) 별도 합성 v5 paired-selector 수집(배정 20/20 응답 수신)에서 strict gate 통과 8/20, 목표 달성 7/20, schema parsing 실패 10/20. Provider 신원/revision/비용/요청 수, 순수 추론 지연, dashboard seed는 미상이며 native pilot에는 controller-v3/v4 수정 교란(1행 vs.\ 2--8행)이 존재한다. 따라서 본 결과는 확인적 질문 A/C, ontology 우월성, 모델 순위 또는 인간 편익이 아닌 범위가 한정된 통합·회계 적합성을 확립한다.
\end{abstract}

본 연구의 기여는 범위가 명시된 proposal-to-commit 통합과 근거 계수 설계다. 수리 정보는 후보를 바꿀 수 있지만 동일한 외부 저작 제약에 대한 재검증만 상태 변경을 허가하며, 관측된 검사와 replay의 증거 한계는 서로 구분한다. C1--C5는 이 계약과 근거를 정리하며 구성 알고리즘의 발명이나 입증된 모델 우위를 주장하지 않는다.

\section{관련 연구와 연구 공백}
Grounding/개연성은 quest/entity·graph quest·memory--reflection--planning·학습형 role을 다루고, player/dialogue·role은 admissibility/experience를 분리한다 \cite{S03_weir2024ontologically,S20_ashby2023personalized,S07_park2023generative,S08_shao2023character,S21_akoury2023player,S22_hochreiter2026beyond,S23_yin2026contextualized,S02_figueiredo2025scaffolded}; engagement affect는 미래·비구현·비권위다 \cite{S24_yannakakis2011experiencedriven,S25_melhart2020engagement,S26_wang2026engagement}. 여기서 다루는 설계 질문은 출처 결속 proposal-to-commit 경로 안에서 상태 변경 권한, 수리 정보, replay 근거를 어떻게 구분할 것인가이며, 선행 연구에 이 구성 요소가 없다는 주장은 아니다.

TextWorld/ScienceWorld, MineDojo, GVGAI, AgentBench, AgentBoard, SOTOPIA, BALROG와 자동 playtesting은 state·embodied·agent/game-content·과정·사회·장기 환경을 보완한다 \cite{S11_cote2019textworld,S12_wang2022scienceworld,S13_fan2022minedojo,S14_perezliebana2019gvgai,S15_liu2024agentbench,S16_ma2024agentboard,S17_zhou2024sotopia,S18_paglieri2025balrog,S19_lepelletier2022playtesting}; NCP-Bench는 narrative commitment/fact consistency이지 player outcome이 아니다 \cite{S58_ma2026ncpbench}. 구조 제약·critic·affordance·trigger rule·precondition/effect·rule refinement·incremental validation·authored transformation·JSONSchemaBench \cite{S09_geng2023grammar,S10_beurerkellner2023prompting,S36_scholak2021picard,S50_kambhampati2024llmmodulo,S51_ichter2023saycan,S52_wang2025agentspec,S53_li2025settingdc,S54_zhou2025story2game,S42_buongiorno2024pangea,S01_vaucher2026ivie,S44_gongora2026worldstate,S57_geng2025jsonschemabench}는 우월성을 확립하지 않으며 G-Retriever/HippoRAG/Mem0 \cite{S04_he2024gretriever,S05_gutierrez2024hipporag,S06_chhikara2025mem0}도 commit authority가 없다.

재현성·평가는 frozen artifact·실패 보존·construct/rater/bias control·justified margin/random effects를 요구한다 \cite{S31_agarwal2021precipice,S33_pineau2021reproducibility,S27_vanderlee2019best,S28_karpinska2021perils,S29_zheng2023judging,S30_chen2024judgement,S32_lakens2018equivalence,S35_barr2013random}; 자원 회계는 에너지·탄소 보고 연구에서 동기를 얻는다 \cite{S34_henderson2020energy}. Replay와 leakage 검사는 배정 분모의 무결성을 뒷받침할 뿐 효능을 입증하지 않으며, replay 검사는 invalid nonfinal attempt도 포함한다 \cite{S56_feng2025agentrr,S59_sun2025bdc}. C1--C5는 enforcement·game-state management·feedback repair·replay·action interposition·precondition/effect·abort·social logic·belief-aware planning을 결합하지만 발명/최초성 주장은 아니다 \cite{S52_wang2025agentspec,S53_li2025settingdc,S54_zhou2025story2game,S45_madaan2023selfrefine,S56_feng2025agentrr,S37_riedl2003managing,S39_fikes1971strips,S40_schneider2000enforceable,S49_haerder1983transaction,S38_evans2013versu,S41_ware2021sabre}.

\section{문제 정의와 보장 경계}
입력 $c_t=(G_t,q_t)$는 typed game snapshot $G_t$와 외부 저작 action-policy/disclosure/quest-stage 제약 $q_t$를 구분한다. Python은 둘을 \texttt{WorldState}에 함께 담는다. locations, reachable locations, object locations, inventory, facts, NPC knowledge, quest stage가 인코딩된 상태를 기술하고 action policies와 forbidden disclosures가 이를 제약한다. \texttt{ActionPolicy}는 required preconditions, allowed/required effects, 허용된 quest-stage target을 정의한다. 이 분리는 개념적이며 Python이 두 독립 객체를 저장한다는 뜻이 아니다. Predicate는 terminal history $h_{<t}$나 log에서 \texttt{WorldState}를 복원하지 않으며 수락 전이는 $G_t$만 바꾸고 policy rotation은 제외한다. Retrieval·score·rationale·memory·future affect는 비권위적이다.

비신뢰 제안 $a_t$를 엄격 parsing한 후, 검증기는 일곱 개의 결정론적 술어를 평가하여 \texttt{ValidationResult(valid, errors, checks\_run)}을 반환하며 이를 다음과 같이 정식화한다.
\begin{equation}
\begin{aligned}
V(c_t,a_t)&=(\mathrm{valid},E_t,C_{\mathrm{run}}),\\
\boldsymbol{v}&=(v_{\mathrm{policy}},v_{\mathrm{pre}},v_{\mathrm{reach}},v_{\mathrm{know}},\\
&\qquad v_{\mathrm{disc}},v_{\mathrm{elig}},v_{\mathrm{stage}})\in\{0,1\}^{7},
\end{aligned}
\end{equation}
여기서 $E_t$는 구조화 오류(code, entity, reason, repair hint 포함), $C_{\mathrm{run}}$은 실행된 일곱 검사 ID 목록이며, $\mathrm{valid}\equiv\bigwedge_{i=1}^{7}(v_i=1)$은 일곱 잠재 술어 결과(policy, precondition, reachability, NPC knowledge, forbidden disclosure, stage eligibility, stage monotonicity)의 논리곱이다. 런타임 계약이 개별 Boolean 일곱 개 대신 통합 \texttt{valid} 플래그와 실행 ID 목록을 반환하므로, 검사별 trace나 필드가 누락된 경우 통과나 실패가 아닌 미관측으로 처리한다. 다음 식은 원래 제안의 전체 transaction이 아니라 단일 현재 후보에 대한 gate다. 여기서 $a_t$는 수리로 바뀔 수 있는 현재 후보이며 $\boldsymbol{v}$는 변경되지 않은 $c_t$에 대한 해당 후보의 검사 결과다. 거부된 시도는 $c_t$를 그대로 두고 제어는 bounded repair 또는 fallback으로 이어지며, 동일 policy에 대한 재검증 통과만 상태 변경을 허가한다.
\begin{equation}
c_{t+1}=\begin{cases}
T(c_t,a_t), & \bigwedge_{i=1}^{7}(v_i=1),\\
c_t, & \text{그 외.}
\end{cases}
\label{eq:transition}
\end{equation}

실제 경로는 제안 $\rightarrow$ 결정론적 검증 $\rightarrow$ 관측 가능한 validity·검사 ID·구조화 오류 $\rightarrow$ 선택적 bounded repair $\rightarrow$ 동일 상태에 대한 재검증 $\rightarrow$ commit 또는 상태 불변 fallback이다. 유효 후보도 적용 직전에 다시 검사하며 repair가 없거나 예산이 소진되면 상태는 불변이다. 아래 guided repair operator는 제안과 오류만 사용하지만 일반 Python repair callback에는 \texttt{WorldState}가 전달되므로 이 입력 제한을 모든 callback의 성질로 일반화하지 않는다. 통제 비교에서는 결정론적 상세 수정과 모델 기반 상세 수정에 동일 제안과 상세 오류를 제공하고 같은 모델의 일반 오류 조건에는 일반 시그널을 제공한다. 이 설계 자체는 비교 결과를 뜻하지 않는다.

Fixture는 다음 불변량을 시험하며 증명은 아니다. \textbf{I1:} validation 소진/commit 전 proposal·controller 실패 불변; \textbf{I2:} callback과 $K\in\mathbb{Z}_{\geq 0}$에서 최대 $K+1$ attempt와 pre-commit 재검증(무deadline wall-clock 보장 없음); \textbf{I3:} 수락 \texttt{CandidateAction.effects}는 승인 quest-stage target을 포함해 \texttt{ActionPolicy.allowed\_effects} 안임; \textbf{I4:} 기록된 초기 스냅샷, 완전하고 순서가 보존된 전이 기록, 동결된 schema 및 결정론적 transition version이 주어지면 replay로 기록된 종단 구조화 상태를 복원할 수 있다. 이는 조건부 상태 복원이지 인증, 의미적 정확성 또는 모델 생성 과정의 재현이 아니다.

가정은 올바른 policy·충실한 추출·deterministic version·반환 callback·단일 프로세스 파일 소유다. Replay는 구조화 전이만 검사하며 repair provenance/prompt/확률 생성/미선언 자연어 함의는 검사하지 않는다.

그림~\ref{alg:commit}의 무의존성 의사코드에서 repair budget은 $K\in\mathbb{Z}_{\geq 0}$이고 Record는 in-memory append, 영속 쓰기는 종단 일관성 검사 뒤다. $(\mathrm{ok},E)$는 $V$와 $\mathrm{ok}:=\bigwedge_{i=1}^{7}(v_i=1)$의 축약이며 $V(c,a).\mathrm{ok}$는 재검증이다.

\section{논의}
본 연구의 guided semantic repair 연산자 $\rho$ \cite{S45_madaan2023selfrefine,S48_shinn2023reflexion,S46_chen2023selfdebug,S47_solarlezama2006sketching}는 deterministic pre-execution 오류를 사용하고, oracle-only arm은 상태를 읽는다. Frozen-case rule 일치/edit-scope 진단은 capability나 ontology 우월성 증거가 아니다.

이번 native runtime pilot은 한 authored quest에서 요청된 \texttt{gpt-6.1-sol}/\texttt{gpt-5.6-sol}, \texttt{medium}, \texttt{general\_rule}/\texttt{ontology}를 condition당 2회 요청한 bounded observation이다. 모델은 typed intent만 생성하고 deterministic planner/checker와 Godot이 권위를 유지한다; source 수정 confound와 provider identity/revision/request count/cost 미상이 남는다.
구현 교란: 첫 행은 controller-v3에서 모델 응답 전에 직렬화 오류로 실패했다. 이후 행 2--8은 모델에 보이는 입력을 바꾸지 않고 JSON 경계 한 줄을 수정한 controller-v4를 사용했으므로 selector/representation 차이를 모델에 귀속할 수 없다.
질문 A(model/stack consistency)와 C(fresh-reference noninferiority)는 미실행이다. A는 고정 source/policy/replay의 substituted model/stack budget-bounded goal completion, C는 sealed assignment의 candidate/fresh reference 비교다. Goal completion은 safety/replay와 다른 endpoint이며, 둘 다 exact identity/revision 및 별도 safety/replay accounting이 필요하다. 현재 pilot은 답하지 않는다. 미래 제작 endpoint는 matched request/evidence부터 동결 mandatory check를 모두 통과한 첫 receipt까지의 time-to-first-all-predeclared-validation-pass이며 unfinished/timeout/fail/stage-not-reached에는 성공 시간이 없다.
제안된 endpoint의 단위는 연속 task-clock 초다.

부록~\ref{app:runtime-identity}의 별도 신원 검증 확장은 실제 응답 모델의 증거 누락으로 중단됐으며 신원이 검증된 새 비교 결과는 얻지 못했다.

\subsection{타당성 위협, 윤리 및 산출물 범위}
\textbf{위협과 경계.} State consistency는 behavioral consistency를 입증하지 않는다 \cite{S55_huang2026beyond}. 또한 narrative coherence도 입증하지 않는다. Predicate/role/Godot/DISC 집합은 latent-state vector가 아니고 declaration expectation은 human gold/holdout이 아니다. Historical/활성 lane은 분모가 달라 합산하지 않는다. Provider identity/revision/request count/cost는 미상이고 source 수정 confound가 있다. 참가자·정서·이해·agency·즐거움·몰입·편익·population·safety-rate·model-ranking·상용 성능을 추론하지 않는다. Unkeyed hash는 authentication이 아니며 replay equality는 semantic correctness가 아니다. 미래 human/affect 연구에는 윤리 심의(ethics review), consent, 최소수집·보존·삭제, opt-out이 이 연구의 설계 요건으로 필요하며, 보상 고지와 calibrated judge는 선행 평가 연구에서 동기를 얻는다 \cite{S27_vanderlee2019best,S28_karpinska2021perils,S29_zheng2023judging,S30_chen2024judgement}.

\section{결론}
\system{}은 bounded C1--C5 authorization/repair/replay/accounting과 출처 결속 한·영 observer를 결합한다. 단일 Codex 사례는 실패·acceptance 경계를 보존하며 모델 성능 근거가 아니다. Native pilot은 8 assigned/7 executed/5 system-goal successes인 bounded observation이며 A/C 확인적 평가·ontology/model 우월성 근거가 아니다. Time-to-first-all-predeclared-validation-pass·traceability·whole-game·repeated-cross-model 평가는 미래이고 historical cohort는 합산하지 않는다.

\section{진단·과거·차단 코호트 기록}\label{app:diagnostic-blocked}
\subsection{별도의 신호 탐색 사례}
기존 과거 서술은 본문 결과 및 전향 파일럿과 별개인 합성 \texttt{missing\_effect} 1건(공통 초기 제안에서 필수 효과 \texttt{signal\_restored} 누락)에 다음 수리 경로를 귀속한다: 결정론적 대조군은 1회 수리 후 commit 및 목표 도달에 성공했고, \texttt{gpt-6-luna} 상세 신호는 오류 코드·누락 효과·수리 힌트로 효과를 복원해 재검증 후 commit 및 목표 도달로 이어졌으며, \texttt{Action rejected.}만 전달한 일반 신호는 빈 효과를 유지해 재검증 실패 후 상태 불변 fallback으로 종료되었다. 그러나 현재 이용 가능한 근거 집합에서는 원본 영수증을 찾을 수 없어 이 귀속을 출처 검증하지 못했다. 따라서 이 문단은 검증되지 않은 과거 메커니즘 서술이지 관측 결과의 재확인이 아니며, 프롬프트·실행 코드 버전 결속도 확립되지 않아 활성 분모와 확인적 근거에서 제외한다.

\subsection{미완료 합성 개발 파일럿 및 과거 파일 계수}
반복적인 하니스 개발 과정에서 실패·중단된 시도가 선택적으로 누락되지 않았음을 입증하기 위해, \path{research/codex_feedback_pilot/public-history-20261111/cohort-inventory.json}(표~\ref{tab:artifact-directory-map})은 총 19개 코호트(과거 17개, v5 2개)의 배정·완료·실패·진행중(\texttt{IN\_PROGRESS})·대기(\texttt{PENDING}) 행 수와 로컬 원본 파일의 SHA-256 digest를 보존한다. 초기 합성 개발 파일럿(v2 evidence 및 v2 diagnostic 코호트, \texttt{gpt-5.6-luna}와 \texttt{gpt-5.6-terra} 각 10개 배정)은 첫 \texttt{missing\_precondition} 배정에서 \texttt{protocol\_error}(\texttt{FAILED})로 중단되거나 \texttt{IN\_PROGRESS}/pending 상태로 남아 유효 모델 응답이 0개였다(민감 정보 노출 방지를 위해 원문 오류는 미보존). 전체 과거 파일 계수(완료/실패/pending)는 최초 파일럿 $0/7/3$(기술적·중단 시도 7건), 초기 selector/native 파일 4개 $0/0/40$, 초기 v2 쌍 $0/0/20$, startup diagnostic $0/2/18$, v3 쌍 $0/0/20$, v4 Luna $10/0/0$(상세 목표 $4/5$, 일반 목표 $4/5$), Terra $0/1/9$이며, 표~\ref{tab:paired-feedback-v5}의 완료된 v5 수집(20행)과 합산하지 않는다.

\subsection{사전 등록 차단 게이트 및 누출 부재 검증}\label{sec:prospective-pilot}
