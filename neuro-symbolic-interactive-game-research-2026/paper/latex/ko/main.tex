\begin{abstract}
대규모 언어 모델은 표현력 있는 퀘스트와 대화를 생성할 수 있지만, 유창하거나 스키마에 맞는 텍스트만으로 제안 이벤트의 실행 가능성, 권한 적합성, 정식 게임 상태와의 일관성이 성립하지는 않는다. 본 논문은 생성된 이벤트를 신뢰하지 않는 트랜잭션 제안으로 취급하는 기호 커밋 게이트 \system{}을 제안한다. 타입 엄격 parser, 외부 행동 정책, 여섯 상태 상대 계열로 묶인 일곱 개의 결정론적 검사가 각 전이를 결정하며, 실패 후보는 최대 $K+1$개의 기록된 시도 안에서 제한 수리로 보낼 수 있고 통과 후보는 변경 직전에 다시 검증한다. Validator-error-guided 연산자 $\rho$는 직전 후보와 typed validation error만 읽으며, 이 오류가 유일한 상태 유래 입력이고 권위 있는 \texttt{WorldState}에 직접 접근하지 않는다. 키 없는 SHA-256 콘텐츠 연결, 상태 의미 replay, 할당 완전 계수가 terminal outcome을 감사 가능하게 만든다. 근거는 네 레인으로 분리한다: 단일 작성 world의 오프라인 적합성, 단일 모델 라이브 스크리닝, runtime 권한 없는 closed-world 지식 그래프 링크 시뮬레이션, 참여자가 없는 Godot engineering slice. 오프라인 레인은 mechanism 적합성만 확립한다. 라이브 레인은 $K{=}1$에서 의도적으로 수리 가능하게 만든 policy-blind regime에 한해 guided 5/5 대 blind 0/5 commit을 관찰했으므로 pilot-only로 남는다. 어느 레인도 모집단 효능, 모델 우월성, 플레이어 경험, 상용 엔진 성능을 확립하지 않는다.
\end{abstract}

\section{서론}
인터랙티브 생성은 언어 과제에 그치지 않는다. 후보 이벤트가 자연스러워도 존재하지 않는 아이템을 요구하거나, 화자가 모르는 사실을 주장하거나, 금지된 퀘스트 정보를 공개하거나, 허가되지 않은 효과를 도입하거나, 퀘스트 단계를 후퇴시킬 수 있다. 실행 가능한 텍스트 환경은 그럴듯한 발화와 유효한 전이의 차이를 명시한다 \cite{S11_cote2019textworld,S12_wang2022scienceworld}. 근거 기반 대화와 개인화 퀘스트 시스템은 퀘스트, 엔터티, 그래프 맥락의 가치를 추가로 보여 주지만 \cite{S03_weir2024ontologically,S20_ashby2023personalized}, 맥락 자체가 정식 상태 변경을 승인하지는 않는다. \textbf{\system{}은 생성된 게임 이벤트를 신뢰하지 않는 트랜잭션 제안으로 취급하며, 정식 상태 변경을 외부의 결정론적 commit gate를 통해서만 허용한다.} 그림~\ref{fig:architecture}는 그러한 트랜잭션 하나를 왼쪽에서 오른쪽으로 읽는다.

구조적 생성 제약은 인접한 문제를 해결한다. 문법 제약 디코딩, 언어 모델 질의 언어, 점진 파서는 생성 구조를 제한할 수 있다 \cite{S09_geng2023grammar,S10_beurerkellner2023prompting,S36_scholak2021picard}. 그러나 구문상 허용되는 이벤트도 현재 세계에 대해서는 거짓일 수 있다. 검색과 메모리는 유용한 근거를 공급할 수 있지만 \cite{S04_he2024gretriever,S05_gutierrez2024hipporag,S06_chhikara2025mem0}, 검색된 내용 역시 상태 전이의 권한 주체가 아니다.

본 논문은 이러한 관심사를 감사 가능한 트랜잭션 프로토콜로 결합한 구현인 \system{}을 제시한다. 현재 기여는 다음과 같다.
\begin{enumerate}
  \item \textbf{C1---계약:} 버전형 신뢰경계 contract와, proposal/replay 경계에서 unknown key와 모호한 타입을 거부하는 type-strict parser (\ref{sec:arch}절; E1);
  \item \textbf{C2---controller:} 여섯 상태 상대 계열에 걸친 검사 7개, bounded repair, unchanged fallback, pre-commit revalidation을 갖춘 validate--repair--commit controller (\ref{sec:repair}절; E1, ENG1);
  \item \textbf{C3---감사:} SHA-256 연결 record, state-semantic replay, episode-continuity check (\ref{sec:audit}절; E1, ENG1);
  \item \textbf{C4---harness:} proposal trace가 존재할 수 없는 경우에도 분류된 terminal row를 유지하는 assignment-complete 오프라인 적합성 harness (\ref{sec:lanes}절; E1);
  \item \textbf{C5---수리:} 동결 repairability class에서 blind retry 및 state-reading oracle과 비교한 typed validator-error-guided operator $\rho(a,E)$ (구현: \texttt{counterexample\_guided\_repair}) (\ref{sec:repair}절; E1, E2).
\end{enumerate}
고정 목표 NPC 운영은 C6이나 C-RESULT가 아닌 additive implementation 및 descriptive screening lane으로 NPC-ENG1/NPC-SCR1 아래 보고한다. 하나의 game-owned Mira goal을 유지하며, 신경 모델은 typed intent와 claim을 제안하고 Python은 bounded public projection에서만 계획하며 Godot이 유일한 canonical writer다. \texttt{player\_request}인 \texttt{acquire\_object}/\texttt{install\_lens}만 물리적 행동을 일으키고, Mira의 유일한 NPC world change는 권한 있는 \texttt{tide\_marks\_hint}의 \texttt{reveal\_hint}이며 \texttt{clarify}/\texttt{negotiate}는 dialogue-only다. 사전 배정은 NPC-ENG1 16개 case와 NPC-SCR1 $12\times3\times2=72$개 row(arm당 24개), 합계 88개(R=40, P=24, O=24)다. P는 authenticated Codex typed intent, R은 작성된 rule interpreter, O는 independent row 0인 same-model-family auxiliary reference다. P/R/O config는 NPC-SCR1에만 적용되며 hard ENG1 conformance와 독립이다. 이는 one-step protocol screening이며 normal-play full-loop episode와 분리된 engineering/provenance evidence이고 efficacy, semantic gold, accuracy ceiling, generalization, human benefit을 주장하지 않는다.
기계 검증되는 기여 매트릭스에서 생성한 표~\ref{tab:contribution-map}은 C1--C5를 선행 주제, 근거 레인, 추론 상한에 결합하고, 표~\ref{tab:evidence-lanes}는 레인을 정의한다.

\section{관련 연구와 연구 공백}
\subsection{인터랙티브 내러티브와 게임 에이전트}
KNUDGE는 퀘스트와 엔터티 명세에 근거한 분기형 NPC 대화를 평가한다 \cite{S03_weir2024ontologically}. 지식 그래프 보조 퀘스트 생성 \cite{S20_ashby2023personalized}, 메모리--성찰--계획 에이전트 \cite{S07_park2023generative}, 학습 가능한 역할 연기 에이전트 \cite{S08_shao2023character}는 근거성과 개연성 있는 행동의 상호보완적 측면을 다룬다. 플레이어 대상 연구는 선호와 지각된 대화 품질을 평가하고 \cite{S21_akoury2023player,S22_hochreiter2026beyond,S23_yin2026contextualized}, 2025년 프리프린트는 역할에 따른 안정성--즉흥성 trade-off를 보고한다 \cite{S02_figueiredo2025scaffolded}. 두 흐름 모두 하드 허용 가능성을 선택적 자연스러움 및 플레이어 경험 구성개념과 분리할 동기를 준다.

경험 주도 생성·관찰자 표식 참여도·vision-language engagement 추론 한계는 future affect work의 동기지만 \cite{S24_yannakakis2011experiencedriven,S25_melhart2020engagement,S26_wang2026engagement}, affect는 비권위적이며 본문 구현에 없다.

\subsection{환경과 벤치마크}
TextWorld와 ScienceWorld는 명시적인 인터랙티브 상태를 제공하며 \cite{S11_cote2019textworld,S12_wang2022scienceworld}, MineDojo는 개방형 지식 집약 embodied 과제를 추가한다 \cite{S13_fan2022minedojo}. General Video Game AI는 에이전트, 게임, 콘텐츠 트랙을 분리한다 \cite{S14_perezliebana2019gvgai}. AgentBench는 이질적인 환경의 에이전트를 연구하고 \cite{S15_liu2024agentbench}, AgentBoard는 과정 수준 진단을 추가하며 \cite{S16_ma2024agentboard}, SOTOPIA는 사회적 상호작용을 평가하고 \cite{S17_zhou2024sotopia}, BALROG는 장기 언어 및 시각 게임 추론을 평가한다 \cite{S18_paglieri2025balrog}. 자동화된 플레이 스타일 에이전트는 상호보완적인 시험 선례이지만 인간 평가를 대체하지 않는다 \cite{S19_lepelletier2022playtesting}. 검토한 환경과 benchmark 안에서 transactional authorization, typed repair, semantic replay, assignment-complete accounting을 하나의 protocol로 결합한 사례를 식별하지 못했다. 이는 범위가 제한된 문헌 검토 소견이며 최초성 주장이 아니다.
NCP-Bench는 장기 인터랙티브 내러티브의 commitment와 fact consistency를 위한 benchmark를 추가하지만, \system{}이나 플레이어 결과를 평가하지 않는다 \cite{S58_ma2026ncpbench}.

\subsection{제약, 신경-기호 검증, 검색}
제약 디코더는 출력 구조를 개선한다 \cite{S09_geng2023grammar,S10_beurerkellner2023prompting,S36_scholak2021picard}. 반면 \system{}은 구조를 독립적인 상태 상대 승인의 입력 조건으로 취급한다. 같은 generate-and-verify 분업은 게임 밖에서 확립되어 있다. LLM-Modulo 프레임워크는 모델이 제안한 계획을 외부의 sound critic이 수락 또는 거부하게 하고 \cite{S50_kambhampati2024llmmodulo}, SayCan은 언어로 제안된 skill을 상태 의존 affordance 검사 뒤에만 허용한다 \cite{S51_ichter2023saycan}. AgentSpec은 LLM 에이전트의 런타임 규칙을 trigger--predicate--enforcement 삼중항으로 표현하고 \cite{S52_wang2025agentspec}, \system{}은 술어를 게임 상태에 고정하며 수리 계약과 리플레이 가능한 레코드를 추가한다. Setting the DC는 D\&D 에이전트를 precondition 검사가 있는 tool call에 근거시키는 반면 \cite{S53_li2025settingdc}, \system{}은 자유 텍스트 제안을 parsing과 외부 policy 평가 뒤에만 허용한다. STORY2GAME은 플레이에 쓰이는 action precondition과 effect를 LLM 스스로 생성하게 하지만 \cite{S54_zhou2025story2game}, 여기서는 policy가 제안자와 독립적으로 저작된다. \system{}은 이 critic을 typed 반례를 반환하는 결정론적 상태 상대 commit gate로 구체화한다. 게임 특화 비교 대상은 서로 다른 경계를 보여준다. PANGeA는 LLM이 설계자 규칙에 따라 콘텐츠를 판정하고 수정하도록 해 검증하고 \cite{S42_buongiorno2024pangea}, IVIE는 기호 검증으로 인터랙티브 픽션 세계를 점진적으로 생성하며 \cite{S01_vaucher2026ivie}, 같은 계보의 2026년 후속 시스템은 LLM을 저작된 world-state transformation 선택으로 제한해 \cite{S44_gongora2026worldstate} 구성상 일관성을 얻는다. 이 논문의 트랜잭션, 감사 레코드, 수리 연산자 질문은 별도의 근거 대상이다. 어느 비교도 우월성을 뜻하지 않으며, 유효성은 각 시스템이 인코딩한 술어에 한정된다.
JSONSchemaBench는 구조적 constrained-output compliance, coverage, quality를 측정하지만, 이는 상태 상대 semantic authorization을 확립하지 않는다 \cite{S57_geng2025jsonschemabench}.

G-Retriever, HippoRAG, Mem0는 subgraph retrieval과 장기 메모리를, Generative Agents와 Character-LLM은 행동 memory와 persona를 다룬다 \cite{S04_he2024gretriever,S05_gutierrez2024hipporag,S06_chhikara2025mem0,S07_park2023generative,S08_shao2023character}. \system{}은 이런 context를 받을 수 있지만 commit authority를 주지 않으며 효익은 측정하지 않았다.

\subsection{감사 가능성과 재현성}
과정 지표, sparse-run caution, reproducibility와 environmental reporting은 failure retention과 frozen artifact를 뒷받침한다 \cite{S16_ma2024agentboard,S31_agarwal2021precipice,S33_pineau2021reproducibility,S34_henderson2020energy}. Human/LLM 평가와 향후 participant 분석에는 construct/rater/bias control, justified margin과 random-effects 구조가 필요하다 \cite{S27_vanderlee2019best,S28_karpinska2021perils,S29_zheng2023judging,S30_chen2024judgement,S32_lakens2018equivalence,S35_barr2013random}. Record-and-replay는 경험 재사용을 지원하지만 \cite{S56_feng2025agentrr}, \system{}은 admitted transition의 semantic replay만 주장한다.
벤치마크 오염 완화 연구는 question-level leakage check의 필요성을 뒷받침하지만, 동결된 denominator를 변경하거나 game-agent efficacy 결과를 만들지는 않는다 \cite{S59_sun2025bdc}.

제한된 novelty는 구성요소가 아니라 구현된 결합이다. 선행 연구는 runtime enforcement \cite{S52_wang2025agentspec}, symbolic game-state management \cite{S53_li2025settingdc,S54_zhou2025story2game}, feedback repair \cite{S45_madaan2023selfrefine}, record/replay \cite{S56_feng2025agentrr}, action interposition \cite{S37_riedl2003managing}, classical preconditions/effects \cite{S39_fikes1971strips}, permitted-transition enforcement \cite{S40_schneider2000enforceable}, transaction abort \cite{S49_haerder1983transaction}, authored social logic \cite{S38_evans2013versu}, belief-aware narrative planning \cite{S41_ware2021sabre}를 각각 다룬다. \system{}은 이를 game-state commit boundary에서 결합한다. C1--C2는 independent contract와 validate--repair--commit을, C3--C4는 checksum-linked/state-semantic replay·episode continuity·assignment-complete accounting을, C5는 typed-error repair를 구현한다. 보고서에 기능이 없다고 해서 구현 전체에 없다고 추론하지 않는다.

\section{문제 정의와 보장 경계}
설명을 위해 시점 $t$에서 validation이 사용하는 controller 입력을 다음과 같이 분해한다.
\begin{equation}
c_t=(G_t,q_t),
\end{equation}
여기서 $G_t$는 typed snapshot field를, $q_t$는 해당 snapshot과 함께 저장되는 외부 작성 action-policy, disclosure, quest-stage 제약을 나타낸다. 종단 record history $h_{<t}$는 \texttt{WorldState} snapshot과 별도로 유지된다. Validation predicate는 이를 읽지 않으며 구현은 log에서 상태를 재구성하지 않는다. 이 one-step model에서 수락된 전이는 $q_t$ 아래 $G_t$를 갱신하고 $q_t$를 그대로 다음 단계로 전달한다. 정책 버전 교체는 이 전이의 범위 밖이다. 검색, 내러티브 점수, 모델 rationale, 메모리 요약, 미래의 감정 추정은 비권위적 proposal context이다.

신뢰하지 않는 proposer가 후보 $a_t$를 출력한다. 타입 엄격 parsing은 알 수 없는 top-level field의 거부를 포함한 공유 candidate-key contract를 먼저 강제하고 선언 스키마를 확립한다. validator는 다음을 반환한다.
\begin{equation}
V(c_t,a_t)=(v_{\mathrm{policy}},v_{\mathrm{pre}},v_{\mathrm{reach}},
v_{\mathrm{know}},v_{\mathrm{disc}},v_{\mathrm{elig}},v_{\mathrm{stage}},E_t),
\end{equation}
여기서 $E_t$는 구조화 오류 집합이다. 상태 변경은 다음과 같다.
\begin{equation}
c_{t+1}=\begin{cases}
T(c_t,a_t), & \bigwedge_{i=1}^{7} v_i=1,\\
c_t, & \text{그 외.}
\end{cases}
\label{eq:transition}
\end{equation}

Controller는 인코딩된 계약 아래 다음 구현 불변량을 주장한다. 파일럿은 이를 일반 정리로 제시하지 않고 deterministic valid, invalid, repair, fallback, replay, fault-injection fixture로 해당 mechanism을 시험한다. \textbf{I1 (소진 실패 불변성):} 예산 $K$까지 반환된 어떤 후보도 검증을 통과하지 못하거나 proposal/controller 실행이 commit 전에 실패하면 반환 상태는 공급된 prior state와 같다. \textbf{I2 (제한된 기록 시도):} 모든 proposal과 repair callback이 반환한다는 조건에서 repair budget $K\geq0$은 최대 $K+1$개의 candidate attempt를 기록한다. 성공적인 commit은 변경 직전 수락 후보에 대한 방어적 validation을 한 번 추가한다. Runtime은 callback deadline을 강제하지 않으므로 I2는 wall-clock 종료 보장이 아니다. \textbf{I3 (효과 권한):} 수락 후보는 \texttt{ActionPolicy.allowed\_effects} 밖의 선언된 fact effect를 \texttt{CandidateAction.effects}에 포함하지 않으며, quest-stage target도 해당 policy에 의해 명시적으로 승인된다. \textbf{I4 (상태 의미적 리플레이):} 동결된 스키마와 결정론적 전이 아래 수락된 trace는 명시된 terminal state를 재구성한다.

이 주장된 불변량은 올바른 정책 작성, 선언된 후보 필드로의 완전하고 충실한 추출, 결정론적 소프트웨어 버전, callback 반환, 단일 프로세스 파일 소유권을 가정한다. 상태 의미적 리플레이는 기록된 구조화 후보와 전이를 재검증하지만, 중간 수리의 provenance, reasoning, prompt, 확률적 생성은 재현하거나 검증하지 \emph{않는다}. 구조화 필드에서 누락된 자연어 함의는 보장 범위 밖이다.

검증 오류는 구조화된 error code로 repair callback에 노출된다. repair는 상태를 직접 변경하지 않으며, 예산 소진 시 변경 없는 결정론적 fallback을 반환한다. 그림~\ref{fig:architecture}이 종단 경로를 나타낸다. 파일럿은 구현된 두 callback을 비교한다. \emph{typed validator-error-guided 연산자} (구현: \texttt{counterexample\_guided\_repair})는 직전 후보 $a$와 typed validator 오류 $E$만을 소비하며, 이 오류가 유일한 상태 유래 입력이고 권위 있는 \texttt{WorldState}에는 직접 접근하지 않는다.
\begin{equation}
\rho(a,E)=a \oplus \textstyle\bigcup_{e\in E}\delta(e),
\label{eq:rho}
\end{equation}
여기서 각 $\delta(e)$는 표~\ref{tab:rho-rules}의 오류 class별 결정론적 edit이고 $\oplus$는 그 field edit들을 적용한다. 각 edit은 오류 entity당 최대 하나의 candidate field만 수정하므로 시도당 변경 field 수는 $|E|$로 유계이고, 동일한 오류 집합 $E$를 두 번 적용할 때에만 고정점이 되며 오류 집합이나 시도가 바뀌는 과정의 수렴을 뜻하지 않는다. 같은 field에서 동시에 요구되고 거부되는 entity는 수리 불가로 선언되어 수정되지 않는다. \emph{상태를 읽는 참조 callback}은 반대로 오류 집합을 폐기하고 정책이 규율하는 field(precondition, effect, 두 quest-stage field)를 권위 있는 상태에서 직접 재구성한다. 이 callback은 선언 무결성 field(required object, used fact, disclosed fact)를 의도적으로 수정하지 않는다. 의존성이나 disclosure의 선언을 지우는 것은 후보를 수리하는 것이 아니라 위반을 게이트 뒤로 세탁하는 것이기 때문이다. 이는 상태 판독 가능 수리에 대한 oracle 상한이며, 그 결과를 배포 가능한 수리 방법의 근거로 읽어서는 안 된다.

\subsection{무결성, 의미적 리플레이, 계수}\label{sec:audit}
각 result row는 키 없는 SHA-256 \emph{무결성 체크섬}을 가지며, proposal outcome은 추가로 trace checksum과 연결된다. 이 hash들은 우발적이거나 시험 대상인 콘텐츠 변경을 탐지하지만 signature, message-authentication code, writer identity가 아니며 콘텐츠와 checksum을 모두 다시 쓸 수 있는 행위자에 대한 보호도 아니다. 의미적 리플레이는 prior state와 기록된 모든 candidate/validation pair를 엄격히 parsing하고, final이 아닌 모든 attempt가 invalid임을 요구하며, terminal transition을 재계산하고, 명시된 final state와 비교함으로써 byte 무결성을 넘어선다. Episode replay는 인접 JSONL record 사이의 상태 연속성도 요구한다. Replay는 candidate $j+1$을 만든 repair-generation 단계를 인증하거나 다시 실행하지 않는다.

Terminal record class는 commit, symbolic fallback, adapter failure, controller failure이다. Controller-failure row는 동결된 assignment denominator에 남고 상태를 변경하지 않지만, candidate outcome이 생성되지 않았다면 완성된 proposal trace가 없어도 된다. 따라서 result completeness가 모든 terminal row의 trace 존재를 뜻하지 않는다. 실행 전 assignment key는 $(\mathrm{run},\allowbreak\mathrm{arm},\allowbreak\mathrm{scenario},\allowbreak\mathrm{seed},\allowbreak\mathrm{model},\allowbreak\mathrm{revision},\allowbreak h_{\mathrm{controller}},\allowbreak h_{\mathrm{input}},\allowbreak h_{\mathrm{prior}})$이다. 집계는 중복, 누락, 예기치 않은 key를 거부하고 symbolic, adapter, controller failure를 각각 보고한다.

\subsection{\textbf{E1} 오프라인 적합성 설계}
파일럿은 다음을 묻는다. (PQ1) 유효 후보는 commit되고 명명된 invalid-policy 사례는 변경 없이 유지되는가? 사례는 의도적으로 설계된 적합성 픽스처이며 모델 또는 게임 모집단의 표본이 아니다. 네 도메인은 validator/state isolation, repair-arm 비교, record/trace fault injection, adapter/accounting contract이다. 모든 repair fixture는 실행 전에 동결된 repairability class를 선언한다. \emph{guided-repairable}(구조화 오류 payload만으로 $\rho$에 충분한 정보가 담김), \emph{oracle-only}(수리에 권위 있는 상태 판독이 추가로 필요함), \emph{irreparable}(구현된 어떤 arm도 commit할 수 없음)이며, 13개 gate fixture는 유효 control 하나와 고립된 음성 12개로 구성되고 12개 repair case는 별도 arm denominator를 이룬다. 각 class별 arm 기대 결과는 fixture 계약의 일부이며, 모든 기대값은 실행 전에 명시한다.

측정치는 정확한 count이다. expected/observed validator-class agreement, rejected 또는 controller-failure 사례의 state mutation, repair arm과 repairability별 commit 및 attempt 결과, 지정된 연산에서 거부된/사전 명세된 detectable fault, replayed/committed trace, rejected/injected manifest violation, 사전 명세한 unknown-key 음성 회귀에 대한 proposal/replay 거부 일치를 센다. 마지막 측정은 결정론적 parser-contract parity이며 실증적 safety outcome이 아니다. Adapter 사례가 지닌 latency 및 token 상수는 입력 스키마가 JSON-Schema \texttt{const}로 고정한 합성값이다. 이 값들은 계수 필드 전파만 확인하며 provider, runtime, device에 대한 측정값이 아니다. 동결된 오프라인 packet은 fixture, assignment, schema, trace를 포함한 result, 코드 revision, checksum을 결합하며, 보고는 재현성과 측정 경계 지침을 따른다 \cite{S33_pineau2021reproducibility,S34_henderson2020energy}.

\subsection{\textbf{E2} 라이브 RQ2 스크리닝}
라이브 확장은 블라인드 동일 후보 retry와 $\rho$를 동일한 $K{=}1$에서 비교한다. 각 셀에서 seed로 구분한 hosted proposer \texttt{gpt-5.6-sol} 호출 5회가 후보 하나씩을 만들고, 두 arm은 같은 최초 후보를 받아 호출 내 제안 차이를 제거한다. 조건은 policy 공개 여부와 자명한 효과 0 경로의 존재를 바꾼다. 동결된 packet은 현재 셀과 폐기된 v1 진단을 함께 보존하고 모든 영수증을 SHA-256으로 결합하며 pilot-only로 표시된다. Seed label은 hosted sampler를 제어하지 않고, hosted revision은 고정되지 않았으며, token 회계는 없고, 구성 상태는 모집단 표본이 아니다. 따라서 $p$-value, confidence interval, 모델 순위 없이 정확한 기술 count와 실패 class만 보고한다.

\subsection{\textbf{E3} KG/온톨로지 링크 제안 시뮬레이션}
세 번째 레인은 권한을 가진 \texttt{WorldState}와 분리된 engineering-only closed-world 시뮬레이션이다. graph node 43개와 reference edge 106개, 검토된 typed edge 24개가 type/domain/range 검사와 competency question 6개를 통과하며, 작성형 질의 6개를 고정 전략 7개로 채점했다. Retained typed-lexical 전략(S2)은 작성된 holdout 6/6을 복원했고($P=R=F_1=1.000$, realistic-tie $\mathrm{MRR}=0.944$, Brier $=0.131$, $\mathrm{Sem}@3=1.000$), degree baseline은 하나도 복원하지 못했다. 이는 구성 결과이며 OWL/SHACL 적합성, 의미 완전성, runtime retrieval, 어떤 효능 주장의 근거도 아니다.

\section{논의}
\subsection{확립 가능한 범위}
동결 pilot은 mechanism behavior만 확립한다. encoded check의 state isolation, 선언된 repair/fallback 경로, 명명된 corruption 거부와 row classification을 확인하며 안정적인 detector 귀속은 하지 않는다.
NPC-ENG1은 synthetic closed-world evidence, NPC-SCR1은 one-step screening이며 normal-play episode는 별도 illustrative artifact다. 발화/model output은 fixed goal을 바꿀 수 없다. Python은 typed intent와 bounded public BFS를 내고 role gate는 player/Mira reveal을 전달하며 replan은 observation을 사용한다. P/R/O는 adapter/control/auxiliary이고 independent row는 0이므로 count는 efficacy, superiority, generalization, human benefit, cost equality, semantic gold 또는 accuracy ceiling을 추정하지 않는다.

Offline state-reading은 $\rho$가 전환할 수 없는 oracle-only 사례를 처리하고, typed error만 쓰는 $\rho$는 guided-repairable class에서 oracle과 일치한다. Live에서 blind retry와의 분리는 그 regime에서만 나타났으며 already-valid/irreparable null, unpinned revision과 quasi-replicated calls는 sample-efficiency/model-capability 주장을 막는다. Self-Refine, Reflexion, Self-Debugging이 선례지만 \cite{S45_madaan2023selfrefine,S48_shinn2023reflexion,S46_chen2023selfdebug}, $\rho$는 deterministic pre-execution error만 소비하고 실패 arm을 격리하며 semantic repair가 아니라 counterexample-guided synthesis와 유사할 뿐이다 \cite{S47_solarlezama2006sketching}.

\subsection{선행연구와의 관계}
\system{}은 constrained decoder \cite{S09_geng2023grammar,S10_beurerkellner2023prompting,S36_scholak2021picard}, 검색 및 메모리 구성요소 \cite{S04_he2024gretriever,S05_gutierrez2024hipporag,S06_chhikara2025mem0}, 실행 가능한 환경과 benchmark \cite{S11_cote2019textworld,S12_wang2022scienceworld,S15_liu2024agentbench,S18_paglieri2025balrog}를 대체하지 않고 보완한다. Process-linked trace는 AgentBoard의 측정 관심사를 구현하지만 \cite{S16_ma2024agentboard} 우월성의 근거는 아니다. 확증 protocol은 아직 실행하지 않았다. 독립 semantic oracle과 실제 blind-retry comparator를 갖춘 사전등록 다중 모델 비교, validity를 맞춘 retrieval/memory ablation, 정당화된 검정력과 mixed-effects 분석을 갖춘 blinded matched-validity 인간 연구가 필요하며, 현재 screening pilot을 대체하지 않는다 \cite{S27_vanderlee2019best,S31_agarwal2021precipice,S35_barr2013random}.

\section{타당성 위협, 윤리, 산출물 범위}
근거의 경계는 아홉 가지다. \textbf{L1:} encoded predicate는 structured field 밖 의미와 행동 일관성을 보지 못하며 서사 품질은 미측정이다 \cite{S55_huang2026beyond}. \textbf{L2:} authored world와 constructed live-state variant 하나로 cross-world, cross-policy, scale 일반화를 할 수 없다. \textbf{L3:} state-reading callback은 oracle이며 offline class와 regime-dependent screening은 일반 repair 품질이나 sample efficiency를 확립하지 않는다. \textbf{L4:} hosted proposer 하나는 revision/token/sampling seed를 고정하지 않으며, E2 screening은 Python--Godot authorization round trip을 측정하거나 benchmark로 확립하지 않는다. \textbf{L5:} participant와 affect data가 없으므로 packet은 engine-local 적합성과 measurement-ready protocol일 뿐 comprehension, agency, enjoyment, immersion, player benefit을 지지하지 않는다. \textbf{L6:} unkeyed hash는 integrity만 보장하고 writer authentication이나 adversarial tamper resistance는 제공하지 않는다. \textbf{L7:} single-writer를 가정하며 concurrent-writer safety는 미검증이다. \textbf{L8:} startup-dominated Godot fixture 하나의 16.7\,ms 초과 sample이라 portability와 real-time 결과가 아니다. \textbf{L9:} 선택된 fixture와 screening cell은 population, safety-rate, model-ranking 추론을 지지하지 않는다. Internal validity는 독립 policy expectation과 fixture leakage 부재에, reproducibility는 frozen software와 artifact에 의존한다.
NPC 경로의 asynchronous deadline, duplicate/late-drop, session/epoch/goal/policy/revision/hash freshness gate는 latency나 quality benefit가 아닌 protocol invariant다. Live 취소는 local HTTP/directive invalidation만 수행하므로 provider가 deadline까지 끝내거나 server bounded trace/cache를 남길 수 있다. 반대로 \texttt{Core.cancel}의 no-publication 보장은 unit/controller-only이며 live route 취소 보장이 아니다. final predicate와 player-request 단계는 game contract에 고정되어 있고 human study, cross-world validation, independent semantic gold label, oracle 또는 recovery efficacy 증거는 없다. Core snapshot replay는 redacted recorded-intent를 epoch별로 모델 호출 없이 재생하고 native replay는 불변 입력을 \texttt{--npc-experiment}/\texttt{engine\_fixture\_reexecution}으로 재실행하며 \texttt{--npc-replay} 명령은 사용하지 않는다.

현재 pilot은 participant 또는 personal telemetry를 처리하지 않는다. Human/affect study와 LLM/crowd judge는 아직 실행하지 않은 planned work이며, 향후 review, informed consent, compensation disclosure, minimization, retention/deletion rule, opt-out, judge calibration과 bias control이 필요하다 \cite{S27_vanderlee2019best,S28_karpinska2021perils,S29_zheng2023judging,S30_chen2024judgement}.

\section{결론}
\system{}은 mutation 전에 payload를 gate하고 linked record/replay로 outcome을 감사한다. Frozen fixture는 conformance를, live screening은 constructed repairable regime에서만 $\rho$와 blind retry를 5/5 대 0/5로 분리하는 pilot count를 제공한다. Godot readout은 committed-snapshot rule/contribution을 드러내지만 cross-model/player/retrieval/memory/affect/commercial benefit은 미검증이다.
NPC는 implemented fixed-goal prototype이다. Python은 typed intent/public-projection BFS를 내고 Godot만 canonical change를 허가한다. State movement, cumulative budgets, observation-only replanning과 zero-call replay는 contract behavior이지 efficacy나 player-benefit 주장이 아니다.

\section*{AI 사용 고지}
Large language model은 prose, code와 test drafting, citation-identity check를 보조했고, hosted model은 별도 표기된 live-screening candidate를 생성했다. 모든 보고 count는 deterministic runner 또는 hash-bound receipt에서 온다. playable slice의 UI 아트(초상, 인장, 패널 텍스처, case-file board, evidence icon, guide vignette)와 prop mesh 하나(evidence desk)는 파일별 provenance를 갖춘 curated AI 생성 asset이며, 그림~\ref{fig:playable-readout}의 모든 상태 값, hash, ledger 줄은 committed snapshot에서 엔진이 렌더링한 것이다. 저자는 claim을 source artifact에 대조했고 내용에 대한 책임을 진다.

\section*{데이터 및 코드 가용성}
Repository에는 implementation, build source, 동결된 offline 및 live packet, 결정론적 평가를 갖춘 playable Godot slice, 그리고 표~\ref{tab:contribution-map}과~\ref{tab:evidence-lanes}를 생성하는 기계 검증 기여·참조 주제·실험 매트릭스가 들어 있다. Reviewer archive나 DOI deposit은 주장하지 않는다.
