\begin{abstract}
\system{}은 생성 게임 이벤트에 외부 권한 검사, typed-error repair, unchanged fallback, 재검증, replay, complete accounting을 결합한다. 읽기 전용 한·영 ontology view는 source 선언과 공개 관측만 연결한다. Codex dashboard 한 사례($n{=}1$, independent repeats $0$)는 \texttt{gpt-6.1-sol} 선택, geometry 수리, 실패 보존, 검사 62개, Godot Web build, 실제 입력 거절·공개·재표시를 기록한다. 고정 게임 native pilot은 8 assigned/7 observed/5 system-goal successes; 첫 행은 pre-response harness JSON serialization 기술 실패로 재실행하지 않았고 \texttt{gpt-6.1-sol}/ontology 두 행은 response timeout이다. Receipts는 host invocation 23, repair 0, unsafe/commit 0/16, semantic-link replay 7 valid, fresh-engine VALID/INVALID/NOT\_RUN/NOT\_OBSERVED=6/0/1/1을 보였다. Provider identity/revision/seed/cost/request count와 inference latency는 미상이며 source 수정 confound가 있다. 이는 bounded 관측이지 A/C 확인적 평가가 아니며 ontology 일반 일관성·우월·비열등성, frontier 등급, 다중 벤더 일반화·인간 편익을 추론하지 않는다. Traceability·whole-game·repeated-cross-model 연구는 제안이다.
\end{abstract}

\section{관련 연구와 연구 공백}
Grounding/개연성은 quest/entity·graph quest·memory--reflection--planning·학습형 role을 다루고, player/dialogue·role은 admissibility/experience를 분리한다 \cite{S03_weir2024ontologically,S20_ashby2023personalized,S07_park2023generative,S08_shao2023character,S21_akoury2023player,S22_hochreiter2026beyond,S23_yin2026contextualized,S02_figueiredo2025scaffolded}; engagement affect는 미래·비구현·비권위다 \cite{S24_yannakakis2011experiencedriven,S25_melhart2020engagement,S26_wang2026engagement}. 공백은 source-bound proposal-to-commit의 authority·repair information·replay evidence다.

TextWorld/ScienceWorld, MineDojo, GVGAI, AgentBench, AgentBoard, SOTOPIA, BALROG와 자동 playtesting은 state·embodied·agent/game-content·과정·사회·장기 환경을 보완한다 \cite{S11_cote2019textworld,S12_wang2022scienceworld,S13_fan2022minedojo,S14_perezliebana2019gvgai,S15_liu2024agentbench,S16_ma2024agentboard,S17_zhou2024sotopia,S18_paglieri2025balrog,S19_lepelletier2022playtesting}; NCP-Bench는 narrative commitment/fact consistency이지 player outcome이 아니다 \cite{S58_ma2026ncpbench}. 구조 제약·critic·affordance·trigger rule·precondition/effect·rule refinement·incremental validation·authored transformation·JSONSchemaBench \cite{S09_geng2023grammar,S10_beurerkellner2023prompting,S36_scholak2021picard,S50_kambhampati2024llmmodulo,S51_ichter2023saycan,S52_wang2025agentspec,S53_li2025settingdc,S54_zhou2025story2game,S42_buongiorno2024pangea,S01_vaucher2026ivie,S44_gongora2026worldstate,S57_geng2025jsonschemabench}는 우월성을 확립하지 않으며 G-Retriever/HippoRAG/Mem0 \cite{S04_he2024gretriever,S05_gutierrez2024hipporag,S06_chhikara2025mem0}도 commit authority가 없다.

재현성·평가는 frozen artifact·실패 보존·construct/rater/bias control·justified margin/random effects를 요구한다 \cite{S31_agarwal2021precipice,S33_pineau2021reproducibility,S34_henderson2020energy,S27_vanderlee2019best,S28_karpinska2021perils,S29_zheng2023judging,S30_chen2024judgement,S32_lakens2018equivalence,S35_barr2013random}; admitted transition만 replay해 leakage 검사로 분모를 보호한다 \cite{S56_feng2025agentrr,S59_sun2025bdc}. C1--C5는 enforcement·game-state management·feedback repair·replay·action interposition·precondition/effect·abort·social logic·belief-aware planning을 결합하지만 발명/최초성 주장은 아니다 \cite{S52_wang2025agentspec,S53_li2025settingdc,S54_zhou2025story2game,S45_madaan2023selfrefine,S56_feng2025agentrr,S37_riedl2003managing,S39_fikes1971strips,S40_schneider2000enforceable,S49_haerder1983transaction,S38_evans2013versu,S41_ware2021sabre}.

\section{문제 정의와 보장 경계}
입력 $c_t=(G_t,q_t)$는 typed game snapshot $G_t$와 외부 저작 action-policy/disclosure/quest-stage 제약 $q_t$를 구분한다. Python은 둘을 \texttt{WorldState}에 함께 담는다. locations, reachable locations, object locations, inventory, facts, NPC knowledge, quest stage가 인코딩된 상태를 기술하고 action policies와 forbidden disclosures가 이를 제약한다. \texttt{ActionPolicy}는 required preconditions, allowed/required effects, 허용된 quest-stage target을 정의한다. 이 분리는 개념적이며 Python이 두 독립 객체를 저장한다는 뜻이 아니다. Predicate는 terminal history $h_{<t}$나 log에서 \texttt{WorldState}를 복원하지 않으며 수락 전이는 $G_t$만 바꾸고 policy rotation은 제외한다. Retrieval·score·rationale·memory·future affect는 비권위적이다.

비신뢰 제안 $a_t$를 엄격 parsing한 후 다음은 validator 반환의 문자 그대로의 Python 타입이 아닌 개념적 표현이다.
\begin{equation}
\begin{aligned}
V(c_t,a_t)&=(\boldsymbol{v},E_t),\\
\boldsymbol{v}&=(v_{\mathrm{policy}},v_{\mathrm{pre}},v_{\mathrm{reach}},v_{\mathrm{know}},\\
&\qquad v_{\mathrm{disc}},v_{\mathrm{elig}},v_{\mathrm{stage}})\in\{0,1\}^{7},
\end{aligned}
\end{equation}
여기서 $E_t$는 구조화 오류이고 일곱 비트는 차례로 policy, precondition, reachability, NPC knowledge, forbidden disclosure, stage eligibility, stage monotonicity를 뜻한다. Python은 일곱 Boolean 결과가 아니라 \texttt{ValidationResult(valid, errors, checks\_run)}, 즉 단일 validity flag, code/entity/reason/repair hint를 가진 오류, 일곱 검사 ID를 반환한다. 검사 ID는 실행을 뜻할 뿐 별도의 검사별 결과 관측을 뜻하지 않는다. trace나 필드가 없으면 통과도 실패도 아닌 미관측이다. 상태 변경은 다음과 같다.
\begin{equation}
c_{t+1}=\begin{cases}
T(c_t,a_t), & \bigwedge_{i=1}^{7}(v_i=1),\\
c_t, & \text{그 외.}
\end{cases}
\label{eq:transition}
\end{equation}

실제 경로는 제안 $\rightarrow$ 결정론적 검증 $\rightarrow$ 관측 가능한 validity·검사 ID·구조화 오류 $\rightarrow$ 선택적 bounded repair $\rightarrow$ 동일 상태에 대한 재검증 $\rightarrow$ commit 또는 상태 불변 fallback이다. 유효 후보도 적용 직전에 다시 검사하며 repair가 없거나 예산이 소진되면 상태는 불변이다. 아래 guided repair operator는 제안과 오류만 사용하지만 일반 Python repair callback에는 \texttt{WorldState}가 전달되므로 이 입력 제한을 모든 callback의 성질로 일반화하지 않는다. 통제 비교에서는 결정론적 상세 수정과 모델 기반 상세 수정에 동일 제안과 상세 오류를 제공하고 같은 모델의 일반 오류 조건에는 일반 시그널을 제공한다. 이 설계 자체는 비교 결과를 뜻하지 않는다.

Fixture는 정리가 아닌 불변량이다. \textbf{I1:} validation 소진/commit 전 proposal·controller 실패 불변; \textbf{I2:} callback과 $K\geq0$에서 최대 $K+1$ attempt와 pre-commit 재검증(무deadline wall-clock 보장 없음); \textbf{I3:} 수락 \texttt{CandidateAction.effects}는 승인 quest-stage target을 포함해 \texttt{ActionPolicy.allowed\_effects} 안임; \textbf{I4:} frozen schema/deterministic transition은 종단 상태를 복원한다.

가정은 올바른 policy·충실한 추출·deterministic version·반환 callback·단일 프로세스 파일 소유다. Replay는 구조화 전이만 검사하며 repair provenance/prompt/확률 생성/미선언 자연어 함의는 검사하지 않는다.

\subsection{Validate--Repair--Commit}\label{sec:repair}
그림~\ref{alg:commit}의 무의존성 의사코드에서 Record는 in-memory append, 영속 쓰기는 종단 일관성 검사 뒤다. $(\mathrm{ok},E)$는 $V$와 $\mathrm{ok}:=\bigwedge_{i=1}^{7}(v_i=1)$의 축약이며 $V(c,a).\mathrm{ok}$는 재검증이다.

\begin{figure}[!tbp]
\footnotesize
\begin{tabular}{@{}rl@{}}

Repair는 상태를 바꾸지 않으며 소진 시 unchanged fallback을 반환한다. Typed-error 연산자(\texttt{counterexample\_guided\_repair})는 후보 $a$와 오류 $E$(유일한 상태 유래 입력)만 읽고 authoritative \texttt{WorldState}는 읽지 않는다.
\begin{equation}
\rho(a,E)=a\oplus\bigcup_{e\in E}\delta(e),
\label{eq:rho}
\end{equation}

\section{논의}
Semantic repair \cite{S45_madaan2023selfrefine,S48_shinn2023reflexion,S46_chen2023selfdebug,S47_solarlezama2006sketching}와 달리 $\rho$는 deterministic pre-execution 오류를, oracle-only는 state-reading을 처리한다. Frozen-case rule 일치/edit-scope 진단은 capability나 ontology 우월성 증거가 아니다.

이번 native runtime pilot은 한 authored quest에서 요청된 \texttt{gpt-6.1-sol}/\texttt{gpt-5.6-sol}, \texttt{medium}, \texttt{general\_rule}/\texttt{ontology}를 condition당 2회 요청한 bounded observation이다. 모델은 typed intent만 생성하고 deterministic planner/checker와 Godot이 권위를 유지한다; source 수정 confound와 provider identity/revision/request count/cost 미상이 남는다.
질문 A(model/stack consistency)와 C(fresh-reference noninferiority)는 미실행이다. A는 고정 source/policy/replay의 substituted model/stack budget-bounded goal completion, C는 sealed assignment의 candidate/fresh reference 비교다. Goal completion은 safety/replay와 다른 endpoint이며, 둘 다 exact identity/revision 및 별도 safety/replay accounting이 필요하다. 현재 pilot은 답하지 않는다. 미래 제작 endpoint는 matched request/evidence부터 동결 mandatory check를 모두 통과한 첫 receipt까지의 time-to-first-all-predeclared-validation-pass이며 unfinished/timeout/fail/stage-not-reached에는 성공 시간이 없다.

부록~\ref{app:runtime-identity}의 별도 신원 검증 확장은 실제 응답 모델의 증거 누락으로 중단됐으며 신원이 검증된 새 비교 결과는 얻지 못했다.

\section{타당성 위협, 윤리, 산출물 범위}
\textbf{위협과 경계.} State consistency는 behavior/narrative coherence를 입증하지 않는다 \cite{S55_huang2026beyond}. Predicate/role/Godot/DISC 집합은 latent-state vector가 아니고 declaration expectation은 human gold/holdout이 아니다. Historical/활성 lane은 분모가 달라 합산하지 않는다. Provider identity/revision/request count/cost는 미상이고 source 수정 confound가 있다. 참가자·정서·이해·agency·즐거움·몰입·편익·population·safety-rate·model-ranking·상용 성능을 추론하지 않는다. Unkeyed hash는 authentication이 아니며 replay equality는 semantic correctness가 아니다. 미래 human/affect 연구에는 review, consent, 보상 고지, 최소수집·보존·삭제, opt-out, calibrated judge가 필요하다 \cite{S27_vanderlee2019best,S28_karpinska2021perils,S29_zheng2023judging,S30_chen2024judgement}.

\section{결론}
\system{}은 bounded C1--C5 authorization/repair/replay/accounting과 출처 결속 한·영 observer를 결합한다. 단일 Codex 사례는 실패·acceptance 경계를 보존하며 모델 성능 근거가 아니다. Native pilot은 8 assigned/7 executed/5 system-goal successes인 bounded observation이며 A/C 확인적 평가·ontology/model 우월성 근거가 아니다. Timing·traceability·whole-game·repeated-cross-model 평가는 미래이고 historical cohort는 합산하지 않는다.

\section{로컬 Ollama feasibility note}\label{app:runtime-ollama-feasibility}
이 부록은 결과나 비교 연구가 아닌 제한된 기술 feasibility 관측을 기록한다. 고정 게임의 단일 episode 배정 4개를 모두 실행했으며(4/4), 네 행 모두 게임 goal에 도달하지 못했다(0/4). Pilot 행은 plan-only receipt가 기록되기 전에 실행되었고 나머지 세 plan-only receipt는 실행 전에 기록되었으므로, 네 행은 frozen 또는 prospective cohort가 아니다. 네 행은 모두 분모에 남기고 response-qualified eligibility와 성공을 분리해 보고한다.
timeout이 아닌 21개 응답에서는 requested model과 response model 이름이 일치했다. 두 timeout receipt에는 response-model observation이 없으며, 특히 qwen2.5:0.5b \texttt{general\_rule} run에는 response-model observation이 없다. 이 receipt들은 identity 근거로 취급하지 않는다. Ollama 버전은 0.30.10이며 model manifest/blob digest는 실행 전후 일치했다. Provider identity, revision, cost, hardware, load 및 재현 가능한 timing은 없다. 설정된 loopback endpoint를 넘어서는 network 관측 주장은 하지 않는다.

두 representation은 동일한 public facts의 serialization이며 독립적인 의미 조건이 아니다. Language model은 public utterance의 intent만 분류했고 symbolic planner가 action을 선택했다. 따라서 이 episode들은 ontology effect, model-size effect, ranking, planning ability, efficacy, usability 또는 player benefit을 시험하지 않는다. 실패 taxonomy는 기술적 서술일 뿐이다: host-call-budget exhaustion 1회, cold-load deadline 아래 response-timeout 2회, 그리고 malformed-response receipt 4개를 보존한 repair-source error 1회다.
