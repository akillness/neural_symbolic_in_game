\begin{abstract}
\system{} combines external deterministic authorization, typed-error repair, unchanged fallback, pre-commit revalidation, semantic replay, and assignment-complete accounting; its read-only bilingual ontology view binds source declarations to public observations without mutation authority.

We report bounded conformance and exploratory observations across three active surfaces: (1) an operator-assisted Codex dashboard case ($n{=}1$, 0 independent repeats) under \texttt{gpt-6.1-sol} with repaired mobile geometry, 62/62 checks, a Godot Web build, and real-input denial/disclosure/redisplay; (2) a fixed-game native pilot on one authored quest (seed 20261024; 8 assigned, 7 observed) yielding 5 system-goal successes, 1 pre-response harness-serializer failure (not rerun), and 2 \texttt{gpt-6.1-sol} ontology timeouts, alongside 23 host invocations, 0 repairs, 0/16 unsafe transitions, 7 valid semantic-link replays, and 6 valid fresh-engine reexecutions (1 \texttt{NOT\_RUN}, 1 unobserved); and (3) a synthetic v5 paired-selector collection (20/20 responses received) where 8/20 passed the strict gate, 7/20 reached the specified goal, and 10/20 failed schema parsing. Provider identity/revision/cost/request count, pure inference latency, and the dashboard seed remain unavailable, and the native pilot carries a controller-v3/v4 revision confound (row 1 vs.\ rows 2--8). Accordingly, these results establish bounded integration and accounting conformance rather than confirmatory questions A/C, ontology superiority, model ranking, or player benefit.
\end{abstract}

\section{Problem Definition and Guarantee Boundary}
$c_t=(G_t,q_t)$ separates the typed game snapshot $G_t$ from externally authored action-policy/disclosure/quest-stage constraints $q_t$. In Python these are carried together by \texttt{WorldState}: locations, reachable locations, object locations, inventory, facts, NPC knowledge, and quest stage describe the encoded state; action policies and forbidden disclosures constrain it. An \texttt{ActionPolicy} specifies required preconditions, allowed and required effects, and allowed quest-stage targets. This is a conceptual separation, not a claim that Python stores two independent objects. Predicates neither read $h_{<t}$ nor reconstruct \texttt{WorldState}; transitions update $G_t$ only, excluding policy rotation. Retrieval, scores, rationales, memory, and future affect lack authority.

After strict parsing of the untrusted proposal $a_t$, the validator evaluates seven deterministic predicates and returns \texttt{ValidationResult(valid, errors, checks\_run)}, which we model as
\begin{equation}
\begin{aligned}
V(c_t,a_t)&=(\mathrm{valid},E_t,C_{\mathrm{run}}),\\
\boldsymbol{v}&=(v_{\mathrm{policy}},v_{\mathrm{pre}},v_{\mathrm{reach}},v_{\mathrm{know}},\\
&\qquad v_{\mathrm{disc}},v_{\mathrm{elig}},v_{\mathrm{stage}})\in\{0,1\}^{7},
\end{aligned}
\end{equation}
where $E_t$ denotes structured errors (with code, entity, reason, and repair hint), $C_{\mathrm{run}}$ lists the seven executed check identifiers, and $\mathrm{valid}\equiv\bigwedge_{i=1}^{7}(v_i=1)$ summarizes the seven latent predicate outcomes (policy, precondition, reachability, NPC knowledge, forbidden disclosure, stage eligibility, and stage monotonicity). Because the runtime contract returns the aggregated \texttt{valid} flag and executed check identifiers rather than seven individual Booleans, an absent per-check trace or omitted field is treated as unobserved rather than passing or failing. The following equation describes a single-current-candidate gate, not the whole transaction for the original proposal. Here $a_t$ is the current candidate, possibly changed by repair, and $\boldsymbol{v}$ denotes that candidate's checks against unchanged $c_t$. A rejected attempt leaves $c_t$ unchanged while control continues through bounded repair or fallback; only passing same-policy revalidation authorizes mutation:
\begin{equation}
c_{t+1}=\begin{cases}
T(c_t,a_t), & \bigwedge_{i=1}^{7}(v_i=1),\\
c_t, & \text{otherwise.}
\end{cases}
\label{eq:transition}
\end{equation}

The operational path is proposal $\rightarrow$ deterministic validation $\rightarrow$ observable validity, check identifiers and structured errors $\rightarrow$ optional bounded repair $\rightarrow$ revalidation against the same state $\rightarrow$ commit or unchanged fallback. A valid candidate is checked again immediately before application; exhausted repair or no repairer leaves the state unchanged. The guided repair operator described below uses only the proposal and errors; the general Python repair callback nevertheless receives \texttt{WorldState}, so the restricted-input claim does not apply to every possible callback. For a controlled comparison, deterministic and model-based detailed repair must receive the same proposal and detailed errors, while the same model's generic-error condition receives a generic signal; no comparison outcome is implied by this design.

Fixtures test invariants, not theorems. \textbf{I1:} validation exhaustion or pre-commit proposal/controller failure preserves state. \textbf{I2:} returning callbacks and $K\in\mathbb{Z}_{\geq 0}$ bound attempts to $K+1$ with pre-commit revalidation; without deadlines, wall-clock termination is not guaranteed. \textbf{I3:} accepted \texttt{CandidateAction.effects} stay within \texttt{ActionPolicy.allowed\_effects}, including authorized quest-stage targets. \textbf{I4:} given the recorded initial snapshot, a complete ordered transition record, and the frozen schema and deterministic transition version, replay can reconstruct the recorded terminal structured state. This is conditional reconstruction, not authentication, semantic correctness, or reproduction of model generation.

Assumptions: correct policy/extraction, deterministic versions, returning callbacks, single-process ownership. Replay checks structured transitions, not repair provenance, prompts, stochastic generation, or undeclared natural-language implications.

Repair cannot mutate state; exhaustion preserves it. Typed \texttt{counterexample\_guided\_repair} reads only candidate $a$/errors $E$ (its sole state-derived input), never \texttt{WorldState}:
\begin{equation}
\rho(a,E)=a\oplus\bigcup_{e\in E}\delta(e),
\label{eq:rho}
\end{equation}
Table~\ref{tab:rho-rules}'s $\oplus$ applies deterministic $\delta(e)$: one field/error entity, at most $|E|$/attempt; conflicting requirements/rejections leave fields unchanged. Fixed points require identical $E$, not convergence. The nondeployable state-reading oracle ignores errors, reconstructs preconditions/effects and both quest-stage fields from state, and never launders violations by deleting required objects/used facts/disclosed facts.

\subsection{Integrity, Semantic Replay, and Accounting}\label{sec:audit}
Unkeyed SHA-256 detects accidental/tested changes, not identity or joint rewriting. Replay checks prior-state/candidate/validation, invalid nonfinal attempts, recomputed final state, and JSONL continuity, never repair. Request$\rightarrow$decision$\rightarrow$result and first-action/one-receipt bindings do not prevent duplicate IDs or impersonation. Terminal classes are commit, symbolic fallback, adapter failure, and controller failure (state/assignment preserved; no completed proposal trace). Pre-execution run/arm/scenario/seed/model/revision keys plus configuration/input/prior-state hashes bind assignments; aggregation rejects duplicate/missing/unexpected keys and separates failures.

\section{Discussion, Threats, Ethics, and Artifact Scope}
Our guided semantic repair operator $\rho$ \cite{S45_madaan2023selfrefine,S48_shinn2023reflexion,S46_chen2023selfdebug,S47_solarlezama2006sketching} uses deterministic pre-execution errors; the oracle-only arm reads state. Rule agreement/edit-scope diagnostics are neither capability nor ontology superiority.
Implementation confound: row 1 failed under controller-v3 before a model response; rows 2--8 used controller-v4 after a one-line JSON-boundary correction with unchanged model-visible inputs, so selector/representation differences are not model-attributable.


The fixed-game pilot is bounded native evidence; no ontology-efficacy test ran. A (model/stack consistency) and C (fresh-reference noninferiority) remain unexecuted and require budget-bounded completion under fixed source/policy, sealed assignments, exact identity/revision fields, and separate safety/replay accounting; it answers neither. Endpoint time is request/evidence receipt to the first receipt passing frozen mandatory checks (time-to-first-all-predeclared-validation-pass); unfinished/timeout/failure/stage-not-reached runs have no successful time.
The proposed endpoint uses continuous task-clock seconds.

The separate identity-required extension in Appendix~\ref{app:runtime-identity} stopped at missing served-model evidence; no identity-qualified new comparison was obtained.

\textbf{Threats and boundaries.} The native pilot has one authored quest and two repeats per cell; comparator power, neutral complete-attempt inventories, and independent traceability scores are absent. State consistency does not imply behavioral consistency \cite{S55_huang2026beyond}. It also does not establish narrative coherence. Predicate/role/Godot/DISC sets are not latent states; declarations are not human gold/holdouts; lanes retain separate denominators. No participant, affect, comprehension, agency, enjoyment, immersion, benefit, population, safety-rate, model-ranking, or commercial-performance inference follows. Hashes do not authenticate; replay equality is not semantic correctness. Any future human/affect study requires ethics review, consent, minimization, retention/deletion, and opt-out as design commitments of this work; compensation disclosure and calibrated judges are motivated by prior evaluation studies \cite{S27_vanderlee2019best,S28_karpinska2021perils,S29_zheng2023judging,S30_chen2024judgement}.


\section{Conclusion}
\system{} combines bounded C1--C5 authorization/repair/replay/accounting with a source-bound bilingual observer. The Codex case/native pilot retain failures and boundaries, not model-performance evidence. Whole-game, time-to-first-all-predeclared-validation-pass, traceability, confirmatory A/C, and repeated-cross-model evaluation remain future; historical cohorts stay unpooled.
