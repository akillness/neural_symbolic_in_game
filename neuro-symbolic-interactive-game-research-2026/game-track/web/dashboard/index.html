Commit gate - live per-node evaluation trace

node state = engine family_states for the last proposal (pass / fail / skipped / not evaluated, no default) · family weight = checks evaluated there, not events routed · green/coral = verdict only

Pulses show only the checks the engine executed for that proposal, in execution order, read from the returned trace. A hold lights the failing check and nothing after it: in-scope checks the engine never reached are marked skipped (the disclosure pair is always evaluated together). Families outside the operation's scope stay hatched, are labelled not evaluated, and are listed as such; that is not a pass. Family weight counts checks evaluated there, not events routed. This is engineering demonstration, not efficacy or usability evidence.
