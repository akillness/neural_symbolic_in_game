## 1. Why this plan exists

The current evidence is not whole-game creation evidence. `research/development-cases/ontology-map-20261023-01/` records one operator-assisted, read-only bilingual dashboard extension: `development_runs=1`, `native_cli_invocations=6`, and `independent_repeats=0`. It has no development comparator and no independent repetition. The observed `5942.665 s` wall time is retained as a descriptive fact about that case only. It is **not** a new endpoint baseline, pure inference latency, productivity measure, or comparator result.

This plan therefore proposes a clean, prospective study of fresh, self-contained Godot microgame creation. It does not reinterpret the old case, create a model result, or authorize paid/provider work. Immutable raw material, archives, frozen results and private intake remain outside this plan.

The protocol companion is `protocol.json`; the Korean plan is `plan.ko.md`. All three files must retain the same IDs, statuses, factors, denominators and stop rules.

## 5. Endpoints, quality and traceability

### Primary endpoint

`time_to_first_all_predeclared_validation_pass` is continuous seconds from delivery of the complete frozen brief/evidence receipt to the first timestamp at which the last applicable acceptance check independently verifies `PASS`.

It includes waiting, planning, tool calls, coding, build/test, repairs, reruns and authorized operator interventions. Unfinished, failed, timeout, safety-stop, blocked and missing-evidence runs remain non-success observations. Their stop time is never substituted as a success time.

### Separate secondary outputs

1. **Quality:** one status per acceptance ID and a run-level all-pass indicator; no composite time/quality score.
2. **Time:** per-run endpoint, censoring/stop reason and cap; no replacement value for a missing success time.
3. **Traceability:** six binary verified-link dimensions, reported separately.

The six traceability dimensions are:

- `D1` exact artifact/activity binding;
- `D2` request → rule version → actual check/result → decision;
- `D3` decision → observed state/diff/no-op outcome;
- `D4` trigger → repair change → rerun → actual result;
- `D5` requirements → implementation → verification, with reverse change → requirement coverage separately;
- `D6` independently exercised audit/replay targets.

Canonical rubric cross-reference: `research/traceability-scoring-20261023/rubric.json` is the planned rubric source. Map `D1→TR01` identity/activity binding, `D2→TR02` decision evidence chain, `D3→TR03` decision-to-effect, `D4→TR04` repair chain, `D5→TR05` bidirectional requirement coverage (forward/reverse separately), and `D6→TR06` independent evidence exercisability. This cross-reference is proposed, not validated or executed.


For every dimension `d`, define `n_d` as applicable units with **all** predeclared links independently verified, and `N_d` as all applicable opportunities in the complete arm-neutral observer inventory. Report `n_d/N_d` and per-link counts separately. A missing required link is `0`, not pass. If the inventory is incomplete, coverage is `INDETERMINATE`, never a complete percentage. Repair is `N/A` only when actual zero repairs are independently verified; a failed repair can still be fully traceable.

### All assigned denominators

- `N_planned_cells`: every representation × system × task-block cell declared before launch, including conditionally blocked cells.
- `N_assigned`: all assigned fresh independent runs.
- `N_launched`: assignments crossing the launch receipt boundary.
- `N_completed`: launched runs with every applicable acceptance check resolved and a complete observer inventory.
- `N_all_acceptance`: per acceptance ID, all applicable launched runs; report pass/fail/not-reached separately.
- `N_all_pass`: runs with every applicable acceptance ID independently verified pass.
- `N_failed`: launched runs with a failed acceptance or validity/safety check.
- `N_timeout`: launched runs stopped at the frozen time cap without first all-pass.
- `N_blocked_unavailable`: planned cells not launched because model/tool/consent/capability prerequisites were absent.
- `N_missing_evidence`: launched runs missing required observer evidence; retain them and mark invalid/indeterminate.
- `N_d`: all applicable observer opportunities for traceability dimension `d`, not only successful runs.
- `N_link`: per-link opportunity denominator within each `N_d`.

Task blocks are the cluster/pair key. Repeated fresh runs are nested in task blocks, not independent task-level populations. Report per-cell distributions before any paired/clustered analysis.
