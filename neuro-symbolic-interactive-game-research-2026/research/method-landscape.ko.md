# 2026 적용 방법론 지도

| 방법 | 게임 적용 | TRACE-RPG에서의 역할 | 주요 실패 모드 |
|---|---|---|---|
| TextWorld식 심볼릭 상태 | 객체·방·인벤토리·행동 전제조건 | 실행 가능한 기준 세계와 도달 가능성 오라클 | 자연어 의미를 모두 표현하지 못함 |
| 그래프 검색/PCST GraphRAG | 현재 퀘스트와 NPC에 필요한 lore만 추출 | 제안기 컨텍스트 최소화와 근거 ID 보존 | 검색 결과가 규칙 준수를 보장하지 않음 |
| KNUDGE식 엔티티·퀘스트 조건화 | NPC 목표·관계·퀘스트 사실로 대화 제한 | 발화 후보 생성과 근거 대조 | 데이터/자산 라이선스, 역할별 효과 차이 |
| LLM 형식화 + Z3/규칙 검사 | 자연어 제안을 술어와 이벤트로 변환 | 하드 커밋 게이트, 반례/unsat-core 수리 | 인코딩하지 않은 상식 오류를 증명할 수 없음 |
| 이벤트 소싱 시간 메모리 | 관찰·발화·상태 변경을 순서 보존 | 결정론적 재생, 기억 충돌 해소 | 검색 메모리를 권위 상태로 오인 |
| 생성적 에이전트 시뮬레이션 | NPC/합성 플레이어 스트레스 테스트 | 희귀 장기 시나리오 생성 | 인간 경험의 대체 증거가 아님 |
| 언어/시각 월드 모델 | 화면과 행동 결과 예측 | 후보 정책·비디오 관찰 보조 | 환각 상태를 canonical state로 채택할 위험 |
| RL 플레이스타일 에이전트 | 다양한 행동 정책으로 탐색 | 경로·난이도·교착 스트레스 테스트 | 실제 플레이어 분포 대표성 부족 |
| BALROG류 멀티환경 평가 | 모델 간 도구사용/게임 수행 비교 | 외부 능력 기준과 일반화 검사 | 프로젝트 고유 규칙 안전성을 직접 측정하지 않음 |
| 불확실성 보정 감정 모델 | 긴장/각성 신호 추정과 적응 | 소프트 목적함수와 안전한 fallback | 긴장·몰입·스트레스 개념 혼동 |

권장 시스템 절제 단계는 `S0 LLM-only → S1 +그래프 검색 → S2 +타입/검증 → S3 +반례 수리 → S4 +시간 메모리 → S5 +감정 적응`이다. 모든 단계는 동일한 후보 예산과 유효성 평가를 공유한다.
