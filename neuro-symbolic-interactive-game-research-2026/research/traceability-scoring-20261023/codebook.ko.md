# 추적성 점수 코드북(제안)

**상태:** `PROPOSED_NOT_VALIDATED`; 프로젝트가 작성한 측정 프로토콜이며 인증 표준도 측정 결과도 아니다.

## 1. 구성개념과 분석 단위

구성개념은 **관측 가능한 요구사항, 산출물, 활동, 판단, 수정 및 결과 사이의 회복 가능한 대응관계**이다. 숨은 사고과정, 개발자 역량, 과제 성공, 정확성, 안전성, 인간 이해도 또는 온톨로지 우월성을 측정하지 않는다.

전향적 수집 전에 다음을 동결한다.

1. 단계 스키마와 사건 분류체계;
2. 각 차원의 팔(arm) 중립 관찰 목록 `U_d`;
3. 필수 링크 목록 `L_d(u)`, 적용성 규칙, 소스/버전 규칙 및 결과 상태 어휘;
4. 시간 측정과 수락 기준 버전; 그리고
5. 평가자 접근권한, 블라인딩 및 판정 순서.

단위는 아래에 정의한 대로 관찰자가 목록화한 시도, 판단, 수정, 요구사항, 변경 또는 감사/재현 대상이다. CLI 호출, 판단, 수정, 검사 기록 및 과제 실행은 **서로 다른 단위 유형**이다. 한 스레드의 호출 6회는 독립 실행 6회가 아니다.

## 2. 이진 링크 앵커

각 필수 링크는 평가자가 정확한 소스/버전을 찾고, 원자료 또는 동결된 근거에서 주장된 관계를 확인하며, 뒷받침 위치(locator)를 기록할 수 있을 때만 `1`로 한다. 단순한 필드 존재, 그럴듯한 그래프, 테스트 이름, 해시 하나 또는 사후 설명은 충분하지 않다.

링크를 검증할 수 없으면 다음 1차 사유 중 정확히 하나를 붙여 `0`으로 기록한다.

| 사유 | 운영상 의미 |
|---|---|
| `missing` | 필수 기록 또는 locator가 없음; 빈 로그만으로 활동 0건을 증명할 수 없음 |
| `stale` | 기록은 있으나 오래된 또는 적용 불가능한 개정/버전을 가리킴 |
| `contradicted` | 접근 가능한 근거가 주장된 관계나 상태와 충돌함 |
| `inaccessible` | 동결된 평가 절차에서 필수 근거에 접근할 수 없음 |
| `unverified` | 근거는 있으나 관계, 시간순서 또는 실제 실행을 확정할 수 없음 |

실제 결과는 별도로 `PASS`, `FAIL`, `NOT_RUN`, `STAGE_NOT_REACHED`, `OUT_OF_SCOPE`, `MISSING` 중 하나로 기록한다. 추적 가능한 실패도 실패다. `STAGE_NOT_REACHED`는 보호된 선행 단계와 사유를 설명할 수 있을 뿐, 후속 검사가 실행되었거나 통과했다는 뜻이 아니다.

## 4. 분모와 결측성

분모는 에이전트가 선택한 추적 목록이 아니라 팔 중립 관찰자의 원시 프로세스, 도구, 변경 및 사건 기록으로 만든다. 재시도, 실패, 무동작 판단, 보류 판단, 보호 단계도 동결 분류체계에 포함한다.

- **완전 연결 분모:** 차원 `d`에서 `N_d = |{u ∈ U_d : applicable(u)=true}|`; `n_d`는 `L_d(u)`의 모든 필수 링크가 검증된 단위 수다. `inventory_complete=true`이고 `N_d>0`일 때만 `n_d/N_d`를 보고한다.
- **링크별 분모(선택적이며 대체 불가):** 같은 동결 단위에서 `l_d / m_d`, 여기서 `l_d = Σ 검증 링크`, `m_d = Σ 적용 필수 링크`. 링크 목록과 단위를 명시한다. 링크별 비율을 완전 연결 커버리지라고 부르지 않는다.
- **불완전 목록:** `coverage=INDETERMINATE`, 관찰된 수와 목록 공백을 보고한다. 완전해 보이는 백분율을 내지 않는다.
- **검증된 0:** 독립 근거로 비적용성이 확인될 때만 `N/A`를 허용한다. TR04에서는 실제 수정 시도 0건이 독립적으로 확인되어야 하며, 빈 로그만으로는 부족하다.
- **단계 보호:** 확인된 선행 단계/가드와 사유를 포함해 `STAGE_NOT_REACHED`로 기록한다. 상태 설명 링크에는 기여할 수 있지만 후속 검증을 `PASS`로 만들지 않는다. 필수 감사/재현 대상을 단순히 시도하지 않은 것은 `N/A`가 아니다.
- **극성:** missing, inaccessible, stale, contradicted, unverified는 비통과 링크 상태다. 분모에서 제거하여 성공으로 만들 수 없다.

## 5. 신뢰도·블라인딩·중첩 단위(전향적 프로토콜)

추적을 만들거나 산출물을 구현하지 않은 평가자를 최소 2명 둔다. 교육, 저자성, 조직적 관계, 접근권한 및 블라인딩 실패를 동결하고 기록한다. 가능한 경우 팔/모델 표지를 가린다. 각 평가자의 판정 전 이진/상태 평가와 locator를 보존하고, 평가를 고정한 뒤에만 판정한다. 합의 라벨로 신뢰도를 계산하지 않는다.

차원별 단위 수, 범주 빈도, 결측/적용성 수, 불일치 행렬, 원시 일치도, 그리고 이진/상태 라벨에 대한 명목 Krippendorff alpha를 **추정 가능한 경우에 한해** 보고한다. 추정 가능한 경우 불확실성도 보고한다. 변이가 없거나 근거가 부족하면 `UNDEFINED` 또는 `NOT_ESTIMABLE`로 보고하며 완전한 신뢰도로 쓰지 않는다. 링크는 판단, 수정, 요구사항, 대상 및 실행 안에 중첩되므로 모든 간선을 독립 표본으로 취급하지 않는다. 이 제안에 대해 파일럿이나 alpha 추정은 실행되지 않았다.

## 6. 고장 통제와 불변성

점수를 보기 전에 통제를 동결한다. 격리 복사본에서 영수증 제거, 시도 ID 교체, 오래된 산출물 개정 결속, 판단/상태 역전, 실패한 수정 누락을 주입한다. `검출된 유효 손상 / 주입된 유효 손상`과 `오탐 / 정상 통제 단위`를 보고하고, 형식 오류·비적용 통제는 별도로 보존한다. 통제 작성자는 블라인드 평가자에게 변이 키를 공개하지 않는다.

정상 중복, 무관한 장식 추가, 의미를 보존하는 형식 변경을 불변성 통제로 넣는다. 이들은 등급을 바꾸지 않아야 한다. 텍스트 로그, 표, 일반 규칙 파일 또는 온톨로지가 같은 의미 링크를 만족할 수 있으며 RDF, 온톨로지 트리플, 특정 문서 배치나 장식 필드를 요구하지 않는다.

감사 부담과 계측 오버헤드를 대칭적으로 기록한다: 단위당 평가자 시간, 검사한 근거 객체 수, 접근 실패, 로깅 또는 운영자 개입 비용. 감사 부담은 보고량이며 추적성 점수가 아니다.

## 7. 주요 시간 종점은 별도

향후 일치 비교에서는 **사전 선언한 모든 검증의 최초 통과까지 걸리는 시간**을 연속 과제 시계 초로 사전 선언한다. 일치하는 완전 요청/근거를 받은 시점부터 모든 필수 검사를 통과한 최초의 정확한 영수증까지이며, 대기, 편집, 도구, 제공자 대기 및 수정 시간을 포함한다. 모든 할당 실행에 완료 상태를 부여하고 실패·미완료·시간 초과 실행에는 성공 완료 시간을 부여하지 않는다.

현재 **5942.665초**는 오래된 사례의 기술적 wall-clock 서술값이며 새로 사전 선언한 전향적 지표가 아니다. TR01–TR06과 합치거나 모델 추론 지연으로 해석하지 않는다. 향후 전체 게임 비교는 `research/development-comparison-20261023/plan.en.md`, `plan.ko.md`, `protocol.json`에 `study_label=development-comparison-20261023`, `task_id=GODOT-MICROGAME-FULL-001`, `status=PROPOSED_NOT_EXECUTED`로 계획되어 있다. 이 코드북은 그 계획을 실행하지 않는다.

## 8. 예시(수집 시험이 아님)

1. **아름다운 온톨로지, 잘못된 영수증(부정 예):** 온톨로지에 모든 예상 간선이 있으나 오래된 개정을 가리킨다. 해당 링크는 `0/stale`, 완전 연결 단위도 `0`이다. 올바른 실행을 결속한 일반 텍스트 로그는 `1`이 될 수 있다. 형식은 기여하지 않는다.
2. **훌륭한 추적, 실패한 수정(추적성 양성·결과 실패):** 촉발 사건, 실제 diff, 재실행 및 실패 결과가 모두 확인된다. TR04는 `1`이지만 결과 상태는 `FAIL`, 완료는 달성되지 않는다. 로그에서 두 번째 관측 수정이 누락되면 결측 링크와 함께 분모에 남는다. 빈 로그는 `N/A`가 아니다.
3. **조기 거부와 부분 QA:** 가드가 실행을 멈추고 상태 커밋이 없다는 근거가 확인된다. 판단/상태/효과 링크는 완전할 수 있지만 후속 검사는 `STAGE_NOT_REACHED`이지 `PASS`가 아니다. 구성 게이트 7개 통과만으로 포인터 잠금 오류나 yaw 가드가 남은 최신 가산 전체 `NOT_PASS`를 뒤집지 못한다.

위 예시는 설명용 구성물이며 수집 시험이나 측정 점수가 아니다.

## 9. 현재 사례의 근거 경계

현재 사례에서 기술적으로 알려진 것은 다음과 같다: 하나의 연결 스레드에서 운영자 보조 Codex 과제 1건; 네이티브 턴 컨텍스트 6개와 CLI 호출 6회; 편집 턴 5회, 코드 수정 라운드 4회, 읽기 전용/무편집 재개 1회; 62개 통과 영수증; 당시 수락 집합에 따른 날짜가 있는 QA10 `PASS`; 이후 가산 전체 QA `NOT_PASS`; 그리고 공개된 파일/해시 결속 107/107 일치(매니페스트 항목 102개와 실제 이미지 5개). 107/107은 바이트 무결성 근거이지 독립 연구, 출판사 승인, 진위 증명 또는 효능 결과가 아니다.

확인되지 않았거나 성립하지 않는 것은 제공자가 반환한 불변 모델 식별자/개정, seed, 비용, 모델 전용 지연, 비교군, 독립 반복(현재 `n=1`, 독립 반복 `0`), 독립적으로 채점된 TR01–TR06 값, 인과적 우월성, 온톨로지 필요성, 인간/플레이어 효익 및 출판사 승인이다. 과거 코호트나 이전 E2 결과를 이 사례로 재명명하지 않는다. 최신 전체 `NOT_PASS`와 날짜가 있는 QA10 `PASS`는 서로 다른 수락 맥락의 별도 기록이다.

## 10. 출처 주석

다섯 개의 1차 출처는 `sources.json`에서 `SRC01`–`SRC05`로 열거한다. 출처는 출처관리, 양방향 추적성, 산출물 심사, 코딩 신뢰도, 검증/확인 구분의 개념을 뒷받침할 뿐 이 프로젝트가 작성한 루브릭을 인증하지 않는다. JCGM의 도량형 추적성은 교정 사슬 개념이며 소프트웨어 근거 추적성과 동의어가 아니다. 새 참고문헌 ID를 추가하지 말고 직접 URL을 인용하며 전문을 재배포하지 않는다.
