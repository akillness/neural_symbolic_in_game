**Method (2026-08-21).** A counterexample-guided repair operator `rho(a,E)` was added in `src/nesy_game/repair.py`. It consumes only the prior candidate and the validator's structured error set, never authoritative `WorldState`, and that boundary is held by a poisoned-state sentinel test. The pilot battery gained a frozen repairability taxonomy and now compares four arms. Over the 12 authored initially-invalid cases at matched budget `K=1`, rejection-only committed `0/12`, blind unchanged retry `0/12`, guided `rho` `5/12`, and the state-reading policy-restore oracle `6/12`; per class, guided commits `5/5` guided_repairable, `0/1` oracle_only, `0/6` irreparable (`C-PILOT-002`, `C-PILOT-006`). References went 42 -> 45; Stage 5 now records 45 identities after `S44`--`S46` were verified live against arXiv and OpenAlex on 2026-08-28, with Semantic Scholar recorded as rate-limited rather than matched.

**Evidence (2026-08-28).** The first non-recorded `ProposalAdapter` (`CodexProposalAdapter`) executed a live screening pilot. The guided-vs-blind separation is regime-dependent: on the frozen base state the proposer returned `5/5` first-shot valid candidates because that state admits a zero-effect valid action, and forbidding a zero-effect action there produced `5/5` invalid candidates whose errors were all `QUEST_STAGE_REGRESSION`, a guided-irreparable class, so both arms committed `0/5`. On the pre-registered `signal-repair-v2` state with the constraint table withheld, live errors fell in the repairable class and guided repair committed `5/5` while blind retry committed `0/5` over the identical per-seed proposal (`C-PILOT-007`). Live errors also co-occur, so a single irreparable code blocks commit even after the repairable ones are cleared (`C-PILOT-008`). Every fallback in every cell preserved the prior state hash.
