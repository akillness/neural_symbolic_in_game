# TRACE-RPG Controller

TRACE-RPG is the unified research artifact synthesized from the original world-generation, NPC-dialogue, and affect-adaptation plans.

At step `t`, canonical state is `c_t = (G_t, q_t, m_t)`: a typed world/knowledge graph, authoritative action/quest/disclosure policy, and immutable event prefix. The uncertain affect estimate `z_t` is non-authoritative context, so the proposer observes `s_t = (c_t, z_t)` but cannot commit it. An independently authored action-policy oracle first rejects omitted requirements and non-allowed effects; precondition, reachability, NPC knowledge, disclosure, quest, and schema checks then determine whether a typed event commits. Invalid candidates leave state unchanged and receive bounded counterexample repair; exhaustion invokes a deterministic fallback.

The repair step is the operator `rho(a,E)`. It reads only the prior candidate `a` and the validator's structured error set `E`, never the authoritative state, which is what makes it model-free and auditable. `rho` edits exactly five error classes -- precondition insert and drop, effect insert and drop, and an unauthorized stage effect -- and declines the rest by contract, because undeclaring a used fact, a required object, or a forbidden disclosure would launder the violation rather than repair it. That split defines the frozen repairability taxonomy: `guided_repairable`, `oracle_only` (repair needs state, so only a reference oracle may commit), and `irreparable`. Two consequences are measured rather than assumed: `rho` matches the state-reading oracle exactly on the repairable class and never on the others, and because live proposer errors co-occur, a single irreparable code blocks a commit even after every repairable code has been cleared.

The research contribution is the controller boundary and traceability rather than a claim that one model is a complete NPC or world engine. The game and research tracks compile separately and interoperate through a versioned event schema.

Trace integrity has two gates. An unkeyed SHA-256 checksum detects accidental or unaudited content drift in the complete outcome and every repair attempt; it is not a signature. Semantic replay then recomputes deterministic validation and state mutation while enforcing that each JSONL record begins from the preceding committed state. A record with a freshly recomputed checksum can therefore still fail replay if it encodes an impossible transition.
